### ADR-123 — Claude permissions hardening: reconcile global vs project settings; protect main from the global git push:* allow
- **Decision:** Created `docs/adr/ADR-123-claude-permissions-hardening.md` (ACCEPTED, concept_only) reconciling the two permission layers Claude Code merges for this project. Project `.claude/settings.json` is a CORRECT no-popup-yet-protected baseline (`defaultMode: acceptEdits` + comprehensive `deny`: push origin main/master + HEAD:main/master (+`-C` variants), `--force`/`-f`, `reset --hard`, `sudo`, `npm publish`, read/write of `.env*`/`secrets/**`/`*.pem`/`*.key`/`.ssh`) — **no change proposed to it**. The divergence is in the global/home `~/.claude/settings.json`: `"Bash(git push:*)"` allow is strictly WIDER than the project deny on push origin main/master and has NO matching global deny; plus `"skipDangerousModePermissionPrompt": true` suppresses the dangerous-mode HITL confirmation. `"Bash(npm:*)"` is likewise wider than the project `npm publish` deny.
- **Why it is a real defense-in-depth gap (not immediate):** Claude Code precedence = enterprise > CLI > project-local > project > user/global, and within the merged set deny > ask > allow. So WHILE this project is the cwd, the project deny DOES override the global `git push:*` allow — push to `main` is blocked here, today. Exposure is structural: (1) protection of `main` depends on EVERY repo shipping the deny list — in any other directory/repo (or a fresh checkout before project settings load) the global `git push:*` stands alone → push to a protected branch auto-allowed; (2) `skipDangerousModePermissionPrompt: true` removes the one interactive barrier that would surface such an action to a human (conflicts with CLAUDE.md §11 / safety-rules / approval-rules stop-barriers). Fail-safe default for a GLOBAL config = deny the dangerous targets at the global layer too, so safety does not hinge on each project re-asserting it.
- **Decision content (3 parts):** (1) narrow global `allow` from blanket `Bash(git push:*)` to a feature-branch-only set (`git push`, `git push origin HEAD`, `git push -u origin HEAD`, `git push --dry-run *`, `git push origin *`) AND mirror the project deny at the global layer (push origin main/master, HEAD:main/master, `--force`/`-f`, `-C` variants) so protected branches + force are blocked EVERYWHERE independent of any project deny (deny>allow); (2) mirror `npm publish` deny globally, replace `npm:*` with explicit subcommand allows; (3) REMOVE `skipDangerousModePermissionPrompt: true` (omit → default false) to restore the dangerous-mode confirmation HITL barrier (CLAUDE.md §11, safety-rules). Additive to / consistent with ADR-027, ADR-120 (terminal pushes branch, never merges), ADR-121, merge canon. Changes NO project file behaviour.
