### sp33b-log-status-report

- **Instruction:** operator-authorised — build a small ops-reporting utility
  `scripts/log-status-report.sh` that walks a shell glob of task-log files
  (default `/tmp/sp*-*.log`), classifies each one's state, and writes a
  single markdown summary (default `~/banxe-dev/DISPATCH-STATUS.md`).
  Prepare-only, draft-PR, no autonomous install. Pattern reference (ADR-102
  reference-not-restate): `scripts/novelty-watcher.sh` +
  `systemd/novelty-watcher.{service,timer}` — shape borrowed, behaviour NOT
  duplicated.
- **Scope of change:**
  - `scripts/log-status-report.sh` — plain bash, `set -euo pipefail`, no LLM
    calls, read-only against every input log (`stat` / `wc` / `grep` /
    `tail` only), atomic write of `$STATUS_PATH` via `mktemp`+`mv -f`.
    Config-over-hardcoding (CLAUDE.md §10): `LOG_GLOB`, `STATUS_PATH`,
    `STALE_SECS` (default 1800), and `JOB_MATCH` all env-driven. `JOB_MATCH`
    intentionally has NO committed default — the operator sets it in the
    local env under the runner-process pattern in use on the host; when
    unset, the header reports `active jobs: n/a (JOB_MATCH unset)` and
    `pgrep` is not invoked. The script exits non-zero if the output
    directory is missing / not writable.
  - `systemd/log-status-report.service` — Type=oneshot, `WorkingDirectory`
    + `ExecStart` anchored to `%h/banxe-architecture`,
    `EnvironmentFile=-%h/.config/banxe/log-status-report.env`, sandbox
    hardening (NoNewPrivileges, ProtectSystem=strict, ReadWritePaths=
    `%h/banxe-dev`). PrivateTmp=no so /tmp reads see the same glob as the
    operator.
  - `systemd/log-status-report.timer` — OnBootSec=30s, OnUnitActiveSec=60s
    default, Persistent=true. NOT enabled by this PR — operator step in
    the runbook.
  - `config/log-status-report.env.sample` — documented sample. No secrets;
    the report is fully non-sensitive ops metadata. Populated file lives
    OUTSIDE the repo at `~/.config/banxe/log-status-report.env` mode 0600.
  - `docs/runbooks/log-status-report.md` — purpose, config, install steps
    (`systemctl --user`), explicit read-only contract, embedded first ~15
    lines of the self-test output.
- **State classification (per spec):**
  - `EMPTY` — file size 0.
  - `FINISHED` — regex `^\[[A-Z].*=.*\]` matches any line.
  - `IN_PROGRESS` — no marker AND mtime younger than `STALE_SECS`.
  - `INCOMPLETE` — no marker AND mtime older than `STALE_SECS`.
- **Self-test:** ran `scripts/log-status-report.sh` against the current
  `/tmp/sp*-*.log` (50 files) — exit 0, `DISPATCH-STATUS.md` created,
  header + config line + active-count present, markdown table lists every
  file with a computed state and summary. All four states observed in the
  same run (`FINISHED=43`, `IN_PROGRESS=1`, `INCOMPLETE=4`, `EMPTY=2`).
  Head lines pasted into the runbook.
