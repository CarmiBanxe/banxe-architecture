### ADR-121 — Parallel-session destructive-action protection (RULE 7): no destructive ops on shared/foreign state; resilience + recovery contract; pre-commit guard
- **Decision:** Created **ADR-121** (PERMANENT canon, ACCEPTED) establishing **RULE 7** — a session MUST NEVER run a destructive op against shared or foreign-session state it did not create: no `rm -rf` on any repo checkout, no deleting/corrupting `.git` (shared OR a linked worktree's `.git/worktrees/` admin), no `git worktree remove`/`prune` of foreign worktrees, no force-removal/update of foreign branches (`branch -D`/`push --delete`/`update-ref -d`), no `chattr`/perm/ownership change on shared `.git`. Cleanup is limited to the session's OWN isolated worktree (ADR-120; `bx-session.sh --cleanup`). RULE 7 is a **stop-barrier** (invariant priority, with `safety-rules.md`); uncertain target ⇒ **fail-closed** (treat as foreign, do not destroy) + escalate.
- **Basis (incident, not invented):** 2026-06-24 the shared checkout `/home/mmber/banxe-architecture` + its `.git` were **deleted mid-session** (external/parallel-session event). Because all **12 linked worktrees** had `gitdir`→`.git/worktrees/`, the single deletion **cascade-orphaned every worktree at once**. **No commits lost** (origin intact); recovered via `git clone`, `main` now at `06fac53`. Root causes: (a) shared `.git` = single point of failure for all linked worktrees; (b) no canon banned destructive ops on shared/foreign state; (c) ADR-120 isolated commits but not the substrate.
- **Resilience (eliminate SPOF):** ADR-121 recommends **independent clone per session** (own `.git`, no shared substrate) so destruction cannot cascade; if the linked-worktree model is kept, the shared `.git` MUST be **operator-protected** (`chattr +i` / backup) and the single-point-of-failure is documented + accepted. Honest limit recorded: RULE 7 binds sessions + the commit-time hook but cannot stop an arbitrary out-of-process `rm` — hence operator-side `.git` protection is required, not optional, under linked worktrees.
- **Recovery contract:** origin = source of truth; no local-only state is canonical. On shared-checkout/`.git` loss → recover via `git clone` from origin. Exact steps captured in **`docs/runbooks/recover-shared-checkout.md`** (audit-first → re-clone → `install-hooks.sh` (`core.hooksPath=.githooks`) → operator `chattr +i .git` → re-establish worktrees via `bx-session.sh`/`git worktree add` off fresh `origin/main`).
- **Memory persistence ("fix it in memory"):** appended **Rule 7** (+ destructive-op ban + resilience + recovery pointer) to `.claude/rules/parallel-session-isolation.md` (after Rule 6) and added the incident + ADR-120/121 to its Anchors, so every future factory/agent session loads RULE 7 across sessions.
- **Enforcement (`.githooks/pre-commit`, extended, minimal-diff, no false-block):** (a) **BLOCK** any commit staging git-internal/worktree-admin paths (`^\.git/` or `*/worktrees/*`) — never a legitimate commit ⇒ zero false-positives; (b) **WARN non-blocking** when a staged **`*.sh`** ADDS a RULE 7 destructive pattern (`rm -rf` / `git worktree remove|prune` / `branch -D` / `push --delete` / `chattr … .git`) — scoped to shell-script added lines so it never false-blocks docs that merely *mention* the patterns (incl. ADR-121 + the runbook) nor normal commits.
- **Proof:** Incident facts above are the recovered state (main `06fac53`; 12 worktrees orphaned; re-clone). `bash -n .githooks/pre-commit` clean. Guard verified BOTH directions: path-guard fires on `.git/config` + `foo/worktrees/bar`, ignores normal paths; danger-regex matches `rm -rf` + `git worktree remove`, ignores `echo hello`.
