### ADR-119 — Stable frozen IL numbering via IL-SEQUENCE.json (ends il_ts re-mint churn)
- **Instrukciya:** Сделать IL-NNN assignment СТАБИЛЬНЫМ — новый shard никогда не renumber-ит прежние записи, устранив ручной il_ts re-mint на каждом behind-PR. Сохранить I-28 append-only, ADR-056/057/059; без ослабления guard. Isolated worktree (Rule 1); local commit only — NO push, NO PR, NO merge.
- **Root-cause:** build_ledger.py (ADR-059) нумеровал IL-NNN по позиции в (il_ts,session_id,path)-sorted скане + FROZEN offset. Shard с ранним il_ts вставлялся в середину и renumber-ил все последующие → guardian-ledger/append-only flag → ручной re-mint il_ts (S6/S7/S8/MIG-*). Churn без семантической ценности.
- **Decision (ADR-119):** заморозить IL-NNN per shard в append-only ledger/IL-SEQUENCE.json (key=<session_id>__<hex>, hex=sha1(path)[:12], collision-proof). (1) init once реплеем legacy (il_ts,session_id,path)+FROZEN-offset нумерации → каждый существующий shard сохраняет ТОЧНО свой номер; (2) known shards reuse frozen number; (3) new shards = max+1 в (il_ts,session_id,path) order, APPEND в IL-SEQUENCE.json (existing keys/values никогда не мутируются/удаляются); (4) ledger рендерится в IL-number order → новая запись всегда tail независимо от il_ts → behind-PR не renumber-ит и не требует re-mint.
