### ADR-143 — Central IL allocator via Redis INCR (atomic cross-process anti-collision; fixes IL-172 dup ROOT cause)
- **Decision:** Replaced the inter-process-unsafe `max+1` mint in `ledger/build_ledger.py:assign()` with an **atomic central counter** (Redis `INCR` on `banxe:il:counter`), used **only at live-mint time**. Two terminals on different worktrees can no longer read the same local `max` and both emit `max+1` (the IL-172 duplicate class). **Three strict modes:** (1) **MINT** (live write, not `--check`) → number from `RedisStreams.incr`; (2) **FALLBACK** (RedisUnavailable) → local `max+1` + loud `WARN … RACE POSSIBLE` (ADR-104 §5 graceful degrade, never crash); (3) **`--check`/rebuild** → `assign(use_allocator=False)`, **never contacts Redis**, fully offline + deterministic (reproduces frozen `IL-SEQUENCE.json` numbers; CI needs no Redis). **Monotonicity:** counter kept `>= max(sequence)` (bump until `> current_max`); existing keys keep their frozen number (append-only, ADR-057/059-A). Native GitHub merge queue is UNAVAILABLE (repo user-owned, org-only) → this allocator provides the serialization instead.
- **Files:** `fabric/common/fabric_redis.py` (+`incr(key)->int`, RESP INCR, fail-closed via `_call`); `ledger/build_ledger.py` (+`_load_fabric_redis`/`_redis_allocate`/`_alloc_next`, `assign(records, use_allocator=...)`, `main` passes `use_allocator=not args.check`); `docs/adr/ADR-143-redis-central-il-allocator.md`; `tests/test_redis_il_allocator.py` (incr monotonic via mocked RESP; fallback on RedisUnavailable; `--check` never touches Redis [offline-determinism]; two concurrent mints over one shared counter → distinct, no collision).
- **Canon:** ADR-119 Rule 8 — IL stays **provisional**, only the SOURCE of the number changes (central counter vs local max+1), still frozen at rebase-before-merge, not hardcoded. ADR-057/059-A — only NEW keys allocated; `IL-SEQUENCE.json` diff add-only; prior records untouched. ADR-104 §5 — Redis down ⇒ warn + fallback, never hard-fail; `--check`/CI never depend on Redis. Config: `TL_REDIS_HOST/TL_REDIS_PORT` (default 127.0.0.1:6379) + vault `REDIS_PASS_FILE` (~/banxe-fabric/.vault/redis.pass), per `gate_exec_consumer.py`.
