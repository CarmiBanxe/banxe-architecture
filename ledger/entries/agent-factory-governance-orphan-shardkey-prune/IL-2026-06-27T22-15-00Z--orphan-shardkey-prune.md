### ADR-144 — Orphan shard_key prune + orphan-detecting --check (close orphan-from-rebase IL class)
- **Decision:** Closed the orphan-IL class in `ledger/build_ledger.py`. ROOT: `shard_key = session+sha1(path)[:12]`; on forced-update/rebuild the path (hence key) changes → old key lingers in `IL-SEQUENCE.json` with no shard (orphan); `assign()` only ever added keys, never removed → orphan accumulates; old `--check` compared by map keys and missed it (the IL-620/#835 bug). **Fix (3 parts):** (A) `prune_orphans(numbering, records)` removes ACTIVE-range keys (`value > frozen_offset`) with no live shard, run in `assign()` BEFORE numbering (orphan no longer inflates base / persists); FROZEN range (`<= frozen_offset`) never pruned (frozen entries legit without entries-shard); live numbers stay frozen (ADR-119). (B) `--check` computes `find_orphans(records, committed_seq)` → **FAIL loudly** "ORPHAN shard_key(s) … run build_ledger.py to prune (ADR-144)" (no silent prune; forces regenerate); stays offline+deterministic (`use_allocator=not args.check`). (C) `check_append_only` exempts orphan removal — an orphan is NOT a recorded IL (no shard), so pruning it does not violate append-only of PRIOR ENTRIES (ADR-057/059-A); removing a LIVE/FROZEN key or mutating a value is still a hard violation.
