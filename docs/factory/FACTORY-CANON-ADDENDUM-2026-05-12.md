# FACTORY-CANON-ADDENDUM-2026-05-12

## Clause F-01 — Single Output Discipline (Factory-wide, mandatory)

1. One assistant response = exactly one actionable artifact.
2. The artifact may be either:
   - one shell command, or
   - one Claude Code prompt,
   but never both in the same response.
3. No parallel next-steps, no alternative command blocks, no chained “do this and then this” in the same output.
4. The next artifact may be produced only after the result of the previous artifact is returned.
5. This is a factory/process rule and therefore belongs to factory canon, not to bank/project implementation canon.

## Clause F-02 — Canon Placement Heuristic

1. Rules about agents, terminals, prompts, shell discipline, output formatting, session transfer, memory limits, repo hygiene, worktree discipline, and factory operating model MUST be stored in factory canon.
2. Rules about bank product behavior, EMI compliance implementation, Keycloak, KYC/AML flows, ledger logic, safeguarding, FCA submission, production architecture, or project delivery roadmap MUST be stored in project canon.
3. Default decision on ambiguity: if the rule governs how the factory builds or manages projects, place it in factory canon first.
4. Do not pollute the bank project with factory-only procedural rules.

## Rationale

The factory is responsible for project creation and operating discipline.
The bank project should contain only project-relevant canon and delivery artifacts.
