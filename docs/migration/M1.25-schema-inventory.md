## Status

**PLAN only — no code, no tests, no ADR, no ledger shard in this step.** The second **meta/inventory**
surface (after the M1.24 advisory-surface *endpoint* manifest): a **static config-as-data inventory
of the advisory DTO/schema families** + reused `__version__` + `source`. Read-only, integer meta only
— **no balances/live/uptime/infra metrics**.

## Deep-read finding — why a CURATED config-as-data list, not an import/reflection scan

`models.py` mixes **advisory** DTOs (`SymbolInfo`, `InstrumentInfo`) with **live/regulated** ones:
`PlaceOrderRequest`, `ExchangeOrderRequest`, `OrderResult`, `CancelResult` (live order management),
`RawOrderBookSnapshot`/`RawOrderBookDiff`/`WsSnapshotMessage`/`WsDiffMessage` (live orderbook/WS),
`NonceResponse`/`VerifyRequest`/`SessionResponse` (SIWE auth), `RateQuote`/`QuoteRequest`/
`QuoteResponse` (quotes). **A programmatic `CamelModel.__subclasses__()` / import-reflection scan
would leak these live/regulated/auth DTOs into a schema inventory** — the same fence violation as the
M1.24 `app.routes` scan.

**Honest scope decision (no fabrication):** M1.25 is an **explicit curated config-as-data list of the
advisory DTO families only** (earn, accounts, assets, instruments, catalogue-meta, breakdown,
manifest), **never an import/reflection scan**, and it **explicitly excludes** the live/regulated/
auth/orderbook/quote DTOs above.

## 1. Scope

**EMI seam (static inventory, config-as-data):** new read-only endpoint (e.g.
`GET /api/v1/catalogue/schema-inventory`) returning a new derived DTO (e.g. `SchemaInventory`): a
`families` list of `SchemaFamily` (`family`, `dto_count`), plus `total_families`, `total_dtos`,
`version` (**reused `__version__`**), and `source`. The list is an **explicit config-as-data
inventory of the advisory DTO families** — **NOT an import/reflection scan** (which would leak
live/regulated/auth DTOs). Path on the catalogue router, distinct (`/catalogue/*` has no `{param}`
route → zero shadow). Frozen DTOs, `catalogue_meta`, and the advisory-surface manifest **not
modified**. The new DTO is a **derived summary**, not a data SoT. Exact path/shape decided in the
M1.25 deep-read (step 0).

**Explicit exclusion:** live/regulated DTOs (`PlaceOrderRequest`, `ExchangeOrderRequest`,
`OrderResult`, `CancelResult`), orderbook/WS DTOs, SIWE auth DTOs (`NonceResponse`/`VerifyRequest`/
`SessionResponse`), and quote DTOs are **never** listed.

## 2. Numeric Invariants (I-01)

- The only numerics are **integer meta counts** (dto_count, total_families, total_dtos) — **NOT
  balances, amounts, positions, ledger postings, prices, APY/yields, computed fees, uptime, latency,
  or any infra/ops metric.** `family`/`version`/`source` are strings. No `Decimal`/`BigNumber`/
  `float` money values; **no balance/posting surface, no fee computation, no observability numerics.**

## 3. Activation Safety

- **Advisory / mock layer ONLY**, a static config-as-data inventory — **NO live orders, execution,
  balances, positions, ledger postings, payments, wallet/custody ops, fund movement; NO live Midaz
  `LedgerPort`/`FeeEnginePort` calls; NO infra/secret/PII/ops/observability metrics.**
- **No import/reflection scan** (fence against leaking live/regulated/auth/orderbook/quote DTOs); no
  network/keys, no prod wiring beyond an additive public route; default sandbox-mock; **fail-closed**
  — the inventory is a fixed curated list; never reflects a non-advisory/live DTO; never fabricates a
  family.

- **No ADR, no code, no tests, no ledger shard in THIS planning step.**

## 6. Spec-fidelity note (M1.16 lesson)

`SchemaFamily.family` (a family label like `earn` / `breakdown`) MUST be specced as a
**non-exhaustive `type: string`** with canonical examples in the description, **never a hard
`enum`** — the inventory grows as advisory DTO families are added. (Per the M1.16 CodeRabbit finding;
re-applied in M1.17–M1.24.)
