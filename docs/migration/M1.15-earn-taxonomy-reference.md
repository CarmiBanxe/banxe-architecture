# M1.15 — earn **taxonomy reference / meta** surface (PLAN, docs-only)

<!-- Source: docs/migration/M1.15-earn-taxonomy-reference.md | Date: 2026-06-18 | Lane: BANXE.RAR → EMI | Server-only (ADR-103) -->

## Status

**PLAN only — no code, no tests, no ADR, no ledger shard in this step.** §4 candidate-1 of the M1
advisory-surface summary: a read-only **earn taxonomy reference** layer over the existing earn SoT.
Deep-read confirms the earn controlled vocabularies (`RiskBand`, `EarnAdvisoryStatus`, lockup
tenor) exist as raw enum/int fields scattered across DTOs, but **no descriptor/reference layer**
explains what each value means. M1.15 adds a read-only `GET /api/v1/earn/taxonomy` reference,
**deriving** descriptive labels over the existing enums — **no second rates/analytics/status
source**. Read-only, **no live money/APY/balances/fees**.

## Why this domain (deep-read)

- `earn/rates.py`: `RiskBand(str,Enum)` = `low`/`medium`/`high`; `_BAND_BY_BASE` (USDC/USDT→low,
  BTC/ETH→medium, else→`_band_for`→high); `RateCard` (`apy_pct: DecimalStr`, `lockup_days: int`,
  `variable_rate: bool`, `risk_band: RiskBand`); `EarnRatesCatalog` Protocol; `EarnRatesResponse`.
- `earn/status.py`: `EarnAdvisoryStatus(str,Enum)` = CREATED/INVESTING/DEPOSITING/WITHDRAWING/
  NORMAL/CLOSED/FAILED/NONE/PROCESSING/COMPLETED/ERROR; `from_legacy` **fail-closes** on
  live-pipeline transaction states (operator-gated, intentionally absent).
- `earn/statement.py`: `EarnStatement` (asset, protocol, current_yield_pct, lockup_days,
  variable_rate, risk_band, fee_summary, advisory_status, source).
- Endpoints today: `GET /earn/rates`, `GET /earn/statement`. **No `/earn/taxonomy`.**

The controlled vocabularies have **no human-facing reference** (label, ordering, lifecycle
grouping, tenor bucketing). That descriptor layer is the advisory gap M1.15 fills — purely
descriptive, derived from the enums.

## 1. Scope

**Legacy area:** none new — M1.15 describes the existing earn vocabularies. **EMI seam (derive):**
new read-only endpoint (e.g. `GET /api/v1/earn/taxonomy`) returning a reference DTO (e.g.
`EarnTaxonomy`) composed of:
- **risk bands** — one entry per `RiskBand` value (code + descriptive label + relative ordering
  low<medium<high + advisory note);
- **advisory statuses** — one entry per `EarnAdvisoryStatus` value (code + label + lifecycle phase
  grouping, e.g. active / terminal / error), explicitly noting that live-pipeline transaction
  states are out-of-scope (operator-gated);
- **lockup tenors** — descriptive tenor buckets/labels for `lockup_days` (e.g. flexible / short /
  locked) as **config-as-data descriptive thresholds**;
- `source` (sandbox-mock).

Assembled by a new `earn/taxonomy.py` enumerating `RiskBand` + `EarnAdvisoryStatus` + a config
tenor table. Existing `/earn/rates`, `/earn/statement` and all earn DTOs unchanged. The new DTO is
a **reference descriptor** (like a catalogue-meta), **not** a data SoT. Exact shape decided in the
M1.15 deep-read (step 0).

## 2. Numeric Invariants (I-01)

- The only numerics are **descriptive config thresholds** (lockup tenor day-count buckets, integer
  ordering) — **NOT APY, yields, balances, amounts, positions, or computed fees.** APY/yield stays
  in `/earn/rates` (not duplicated). Any decimal-valued field uses `DecimalString` and remains
  descriptive config; **no `BigNumber`/`float`, no fee computation.**

## 3. Activation Safety

- **Advisory / mock layer ONLY**, a static derived reference — **NO live orders, stake/unstake,
  execution, balances, positions, payments, fee computation, or fund movement.**
- No live catalogue/exchange calls, no network/keys, no prod wiring beyond an additive route;
  default sandbox-mock; **fail-closed** — the taxonomy is deterministically derived from the enums
  + config; never fabricates a value or surfaces a live-pipeline/operator-gated status.

## 4. Duplication Audit (ADR-102) — MANDATORY before any M1.15 code

1. Repo-wide search for any earn taxonomy/reference/meta surface — esp. `earn/rates.py`
   (`RiskBand`/`RateCard`/`EarnRatesCatalog`), `earn/status.py` (`EarnAdvisoryStatus`),
   `earn/statement.py`, `earn/crypto_earn.py` (`EarnMetrics`), `dse/models.py`, `api/earn.py`.
2. **Canonical earn SoTs (reuse/derive, do NOT duplicate):** rates/yield = `earn/rates.py`
   (`RateCard`/`EarnRatesCatalog`/`earn_rates`); risk band = `RiskBand` + `_BAND_BY_BASE`/`_band_for`;
   status = `earn/status.py` (`EarnAdvisoryStatus`); analytics = `dse/models.py AnalyticsContext` +
   enrichment; statement = `earn/statement.py`. M1.15 **describes/derives** the enum vocabularies —
   it must **not** re-derive APY/yield, create a second status/analytics source, or a second
   risk-band map.
3. The new `EarnTaxonomy` DTO is a **reference descriptor** (descriptive labels over existing enum
   values), not a data source.
4. **`FeeEnginePort` = fee SoT** — not touched (`fee_summary`/`fee_schedule_ref` only referenced if at all).
5. Source-of-truth + every consumer; keep/merge/delete + risks; doubt → fail-closed + escalate.

### Frozen contracts (must not break)
`EarnMetrics`, `EarnAlternative`, `AnalyticsContext`, `EarnRatesResponse`, `RateCard`, `RiskBand`,
`EarnAdvisoryStatus`, `EarnStatement`/`EarnStatementResponse`, and the M1.7–M1.14 contracts
(accounts metadata, asset catalogue, instrument params, `InstrumentInfo`, `InstrumentAssetXref`,
`CatalogueMeta`, `SymbolInfo`, `MarketDataPort`, `FeeEnginePort`).

## 5. Out-of-scope (strictly NOT in M1.15)

- **All P0 / regulated / live parts:** live orders, stake/unstake, execution, balances, positions,
  payments, fund movement; live-pipeline earn transaction states (operator-gated, kept absent).
- **APY/yield re-derivation** (owned by `/earn/rates`); **fee computation/billing** (`FeeEnginePort`).
- **KYC/AML**, cards, crypto-wallet ops.
- **No second rates/analytics/status source, no second risk-band map, no new earn data DTO** beyond
  the descriptive reference; **no contract-breaking changes** to earn DTOs/enums.
- **No user migrations, no DB migrations, no schema changes, no live state machines.**
- **No ADR, no code, no tests, no ledger shard in THIS planning step.**
