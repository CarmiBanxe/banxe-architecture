## Part B — M1.7 PLAN: wallets/accounts advisory metadata (read-only)

### Domain selection (mapping rationale)
Per `banxe_to_emi_mapping.md`, the remaining P1 wrap domains are **wallets/accounts → Midaz
LedgerPort** (best-tested legacy slice), **KYC/AML → compliance stack**, **crypto-api → crypto
port**. Selection for lowest-blast-radius **advisory**:
- **KYC/AML** — **deferred**: a compliance contour (CLASS_B/C governance gate, Ruflo/MLRO,
  CLAUDE.md hard rules); not lowest-blast-radius.
- **crypto-api** — **deferred**: fund/transaction-adjacent (live crypto wallet API).
- **wallets/accounts (Midaz LedgerPort, ADR-013)** — **chosen**: best-tested legacy slice;
  M1.7 takes only a **read-only descriptive metadata** slice of it (account/wallet *capability*
  descriptors), with **all balances / ledger operations / money movement strictly out-of-scope**.

### Scope
- **Legacy area:** `banxe` wallets/accounts (TS/NestJS) — the **descriptive** account/wallet
  metadata only: account types, supported assets/currencies, wallet capabilities/limits-as-config
  (NOT balances, NOT transactions).
- **EMI seam:** a new **read-only advisory** wallets-metadata surface in `banxe-trading-backend`
  (a thin advisory port, analogous to the earn advisory seam) **OR** an advisory descriptor exposed
  via the existing BaaS surface — the exact seam/DTO is decided in the **M1.7 deep-read (step 0)**.
  It maps toward the EMI Banking Core **Midaz LedgerPort (ADR-013)** but **wraps only descriptive
  metadata**, never the LedgerPort's live operations.

### Numeric Invariants (I-01)
Any numeric descriptor (e.g. configured min/max/precision per asset) MUST be `Decimal` /
`DecimalString` via the established normalizer — **no `BigNumber`, no `float`** outward,
fail-closed. **No balance/amount values** are surfaced (those are live, out-of-scope).

### Activation Safety
- **Advisory / mock layer ONLY** — descriptive account/wallet metadata; **NO live balances,
  NO positions, NO ledger operations, NO transfers/payments, NO fund movement.**
- **No live Midaz/LedgerPort writes or reads of real accounts**; no prod wiring change, no
  feature-flag bypass, no network/keys. Default mock; fail-closed for non-wired/unsupported.

### Duplication Audit (ADR-102) — MANDATORY before any M1.7 code
1. Repo-wide search for existing wallet/account/ledger/balance representations — esp.
   `ports/wallet_auth_port.py`, any account DTO, `models.py`; and the architecture's LedgerPort
   (ADR-013) to avoid a second account-metadata SoT.
2. Confirm the EMI Banking Core / Midaz LedgerPort is the **canonical account SoT** — M1.7 must
   **wrap/describe**, not duplicate or re-model it.
3. Source-of-truth + every consumer; no parallel wallets model; keep/merge/delete + risks.
4. Doubt → fail-closed + escalate.

### Out-of-scope (strictly NOT in M1.7)
- **All P0 / regulated / live parts:** real balances, positions, ledger postings, transfers,
  payments, fund movement, live Midaz/LedgerPort operations.
- **KYC/AML, crypto-api, payments, cards** — separate domains/subtracks.
- **No user migrations, no DB migrations, no schema changes, no live state machines.**
- **No contract-breaking changes** to existing EMI contracts; new metadata is additive/advisory.
- **No ADR, no code, no tests, no ledger shard in THIS planning step.**

### Execution outline (for the eventual M1.7 code subtrack — not this PR)
0. **M1.7 deep-read** (server-side, ADR-103) — read legacy wallets/accounts descriptive structure +
   the EMI LedgerPort/account seam; propose the advisory-metadata shape. 1. **Duplication Audit**
   (above). 2. Mock-safe read-only advisory metadata DTO + characterization / contract (frozen) /
   negative fail-closed tests. 3. Append-only IL-shard + promotion PR with the canonical 7 sections.
   Each step server-only; merge operator-gated.
