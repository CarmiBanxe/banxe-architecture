# M1.16 — catalogue **breakdown** (asset-class counts) (PLAN, docs-only)

<!-- Source: docs/migration/M1.16-catalogue-breakdown.md | Date: 2026-06-18 | Lane: BANXE.RAR → EMI | Server-only (ADR-103) -->

## Status

**PLAN only — no code, no tests, no ADR, no ledger shard in this step.** §4 candidate (catalogue-meta
enrichment) of the M1 advisory-surface summary. A read-only **breakdown** surface deriving
per-`asset_class` counts (crypto / stablecoin / fiat) from the existing asset catalogue. Read-only,
**no live money/APY/balances/fees**. Added as a **separate** endpoint/DTO so the frozen M1.14
`CatalogueMeta` stays untouched.

## Domain selection (chosen vs alternative)

- **Catalogue breakdown — CHOSEN.** Pure **integer meta counts** grouped by the existing
  `CryptoAssetMetadata.asset_class` — the read-only step furthest from money/regulatory, derived
  from the already-migrated `asset_catalog`. No money, no APY, synchronous, no app-state.
- **earn taxonomy↔rates cross-reference — DEFERRED.** It would re-surface APY-bearing `RateCard`
  values (yield/money-adjacent) and is async/`app.state`-dependent — higher blast radius and closer
  to money than a pure count breakdown. Revisit later if needed.
- **fee-descriptor reference-only / KYC-AML — deferred** (fee SoT / compliance gate).

## 1. Scope

**Legacy area:** none new — M1.16 summarises the existing asset catalogue by class. **EMI seam
(derive):** new read-only endpoint (e.g. `GET /api/v1/catalogue/breakdown`) returning a new derived
DTO (e.g. `CatalogueBreakdown`): a list of `AssetClassCount` (`asset_class`, `count`) computed by
grouping `asset_catalog(market_data).assets` on `asset_class`, plus `total` and `source`. Distinct
path — does **not** clash with the existing `GET /catalogue/meta`. The frozen `CatalogueMeta` /
`catalogue_meta` (M1.14) are **not modified**; existing endpoints unchanged. The new DTO is a
**derived summary** (like `CatalogueMeta`), not a data SoT. Exact path/shape decided in the M1.16
deep-read (step 0).

## 2. Numeric Invariants (I-01)

- The only numerics are **integer meta counts** (per-class cardinalities + total) — **NOT balances,
  amounts, positions, prices, APY/yields, or computed fees.** `asset_class`/`source` are strings.
  No `Decimal`/`BigNumber`/`float` money values; **no APY re-derivation, no fee computation.**

## 3. Activation Safety

- **Advisory / mock layer ONLY**, a derived read-only summary — **NO live orders, execution,
  balances, positions, payments, fee computation, fund movement; NO infra/secret/PII/ops metrics.**
- No live catalogue/exchange calls, no network/keys, no prod wiring beyond an additive public route;
  default sandbox-mock; **fail-closed** — counts derive from the existing fail-closed `asset_catalog`
  (malformed entries already skipped upstream); never a fabricated count or class.

## 4. Duplication Audit (ADR-102) — MANDATORY before any M1.16 code

1. Repo-wide search for any catalogue breakdown / per-class count surface — esp. `meta/catalogue.py`
   (`CatalogueMeta`/`catalogue_meta`), `assets/catalog.py` (`asset_catalog`/`_ASSET_META`/
   `CryptoAssetMetadata.asset_class`), `api/catalogue.py`, `api/assets.py`.
2. **Canonical SoTs (reuse/derive, do NOT duplicate):** asset metadata + class = `assets/catalog.py`
   (`_ASSET_META`/`asset_catalog`/`CryptoAssetMetadata.asset_class`); flat catalogue counts +
   version = `meta/catalogue.py` (`catalogue_meta`/`CatalogueMeta`, **not modified**). M1.16
   **derives** the class breakdown — **no second registry, counter store, version source, or asset
   map**, and does **not** mutate `CatalogueMeta`.
3. The new `CatalogueBreakdown` DTO is a **derived summary**, not a data source.
4. **`FeeEnginePort` = fee SoT** — not touched.
5. Source-of-truth + every consumer; keep/merge/delete + risks; doubt → fail-closed + escalate.
