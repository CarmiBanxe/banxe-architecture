# M1.17 — markets **breakdown** (per-base / per-quote counts) (PLAN, docs-only)

<!-- Source: docs/migration/M1.17-markets-breakdown.md | Date: 2026-06-18 | Lane: BANXE.RAR → EMI | Server-only (ADR-103) -->

## Status

**PLAN only — no code, no tests, no ADR, no ledger shard in this step.** A read-only **markets
breakdown** deriving per-base-asset and per-quote-asset market counts from the existing
`list_instrument_asset_xref` bundle. Mirrors the approved M1.16 asset-class-breakdown pattern.
Read-only, **no live money/APY/balances/fees**.

## Domain selection (chosen vs alternative)

- **Markets breakdown — CHOSEN.** Pure **integer meta counts** derived from
  `list_instrument_asset_xref` (each `InstrumentAssetXref` carries `base_asset.asset` /
  `quote_asset.asset`). It reuses the **already-approved M1.16 breakdown pattern**, is furthest
  from money/yield, synchronous, and the lowest blast-radius.
- **earn taxonomy↔rates xref — DEFERRED.** A band→rate-card reference mapping would re-surface
  APY-bearing `RateCard` values (yield/money-adjacent); deferred until **explicit operator risk
  acceptance**.
- **fee-descriptor reference-only / KYC-AML — deferred** (fee SoT / compliance gate).

## 1. Scope

**Legacy area:** none new — M1.17 summarises the existing markets bundle by base/quote asset.
**EMI seam (derive):** new read-only endpoint (e.g. `GET /api/v1/markets/breakdown`) returning a new
derived DTO (e.g. `MarketsBreakdown`): `by_base` and `by_quote` lists of `MarketAssetCount`
(`asset`, `count`) computed from `list_instrument_asset_xref()` by counting `base_asset.asset` /
`quote_asset.asset`, plus `total` (number of markets) and `source`. Distinct path — `/markets`
(exact list) has no `{param}` route, so `/markets/breakdown` does not clash. The frozen
`InstrumentAssetXref`, `CatalogueMeta`, `CatalogueBreakdown` are **not modified**; existing
endpoints unchanged. The new DTO is a **derived summary**, not a data SoT. Exact path/shape decided
in the M1.17 deep-read (step 0).

## 2. Numeric Invariants (I-01)

- The only numerics are **integer meta counts** (per-base, per-quote, total markets) — **NOT
  balances, amounts, positions, prices, APY/yields, or computed fees.** `asset`/`source` are
  strings. No `Decimal`/`BigNumber`/`float` money values; **no APY/rate re-surface, no fee
  computation.**

## 3. Activation Safety

- **Advisory / mock layer ONLY**, a derived read-only summary — **NO live orders, execution,
  balances, positions, payments, fee computation, fund movement; NO infra/secret/PII/ops metrics.**
- No live catalogue/exchange calls, no network/keys, no prod wiring beyond an additive public route;
  default sandbox-mock; **fail-closed** — counts derive from the existing fail-closed
  `list_instrument_asset_xref` (unresolvable markets already skipped upstream); never a fabricated
  count or asset.

## 6. Spec-fidelity note (M1.16 lesson)

Any enumerable field in the OpenAPI spec MUST be documented as a **non-exhaustive string**, not a
hard `enum`, when the runtime set can grow. Here `MarketAssetCount.asset` is a free asset string
(e.g. BTC / ETH / EUR, but any catalogued asset) — spec it as `type: string` with canonical
examples in the description, **never** a closed `enum`. (Per the M1.16 CodeRabbit finding where a
hard `enum` diverged from runtime.)
