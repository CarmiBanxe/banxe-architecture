# M1.8 — crypto **asset advisory catalogue metadata** (PLAN, docs-only)

<!-- Source: docs/migration/M1.8-crypto-asset-advisory-metadata.md | Date: 2026-06-18 | Lane: BANXE.RAR → EMI | Server-only (ADR-103) -->

## Status

**PLAN only — no code, no tests, no ADR, no ledger shard in this step.** Next
lowest-blast-radius **advisory** subtrack after M1.7 (account metadata), **not greenfield**.
A new **read-only crypto-asset advisory catalogue** (descriptive per-asset metadata),
**reusing** the existing symbol/asset universe — **no live wallet, no balances, no
transactions, no money movement**. Chosen over the KYC/AML wrap (compliance governance gate,
deferred) and over the live crypto-**wallet** API (fund/regulated, out-of-scope); only the
legacy `crypto-api` **descriptive catalogue** slice is taken.

## Why this domain (mapping rationale)

`banxe_to_emi_mapping.md`: `crypto-api` (TS, 1,275) → EMI crypto wallet API, **wrap**, P1.
M1.8 takes the **lowest-blast-radius, non-fund** slice of it: the **descriptive asset
catalogue** (which assets exist, their display/network metadata), surfaced read-only — it does
**not** wrap wallet balances/transactions (those are fund/regulated, operator-gated). KYC/AML
stays deferred (compliance gate).

## 1. Scope

**Legacy area:** `banxe-crypto-api` descriptive asset catalogue — supported crypto assets,
their display name, asset class, networks/chains, display decimals/precision. **Descriptive
only** (NOT balances, NOT transactions, NOT deposit/withdraw operations).

**EMI seam (reuse + small additive):** a new read-only advisory **asset-metadata** view in
`banxe-trading-backend`, **reusing the existing asset universe** from `MarketDataPort.list_symbols()`
/ `SymbolInfo` (`base_asset`/`quote_asset`) as the single source of *which assets exist*, plus
**config-as-data** descriptive per-asset metadata (name, asset_class, networks, decimals). The
exact DTO/seam is decided in the **M1.8 deep-read (step 0)**. Strategy: **wrap/extend** — no
second asset universe.

## 2. Numeric Invariants (I-01)

- `display_decimals`/precision are **integers** (not money). Any decimal-valued config (e.g. a
  min display unit) MUST be `Decimal`/`DecimalString` — **no `BigNumber`, no `float`** outward.
- **NO balance / amount / posting / transaction values** are surfaced (those are live,
  out-of-scope). The catalogue is descriptive metadata only.

## 3. Activation Safety

- **Advisory / mock layer ONLY**, **config-as-data** — describes assets; **NO live wallet, NO
  balances, NO transactions, NO deposits/withdrawals, NO transfers, NO fund movement.**
- **No live crypto-api/wallet calls, no network/keys, no prod wiring** beyond an additive
  router; default sandbox-mock; **fail-closed** for malformed/unsupported config.

## 4. Duplication Audit (ADR-102) — MANDATORY before any M1.8 code

1. Repo-wide search for existing asset/symbol/instrument/catalogue representations — esp.
   `models.py` (`SymbolInfo`, `InstrumentInfo`), `ports/market_data_port.py` (`MarketDataPort`,
   the mock symbol catalogue), `api/symbols.py`.
2. **Canonical symbol/instrument SoT = `SymbolInfo`/`InstrumentInfo` + `MarketDataPort`** (mock
   catalogue; the real catalogue source is the ADR-021 governance TODO). M1.8 **reuses** the
   asset universe from it — it must **not** create a second asset list / second symbol SoT.
3. The live crypto-**wallet** catalogue (balances/transactions) is **out-of-scope** (fund SoT
   elsewhere; not duplicated, not called).
4. Source-of-truth + every consumer; keep/merge/delete + risks; doubt → fail-closed + escalate.

## 5. Out-of-scope (strictly NOT in M1.8)

- **All P0 / regulated / live parts:** wallet balances, transactions, deposits/withdrawals,
  transfers, payments, fund movement, live crypto-api/wallet operations.
- **KYC/AML** (compliance gate), **cards/banxe-digital**, **payments** — separate subtracks.
- **No second asset/symbol SoT**; no change to `SymbolInfo`/`InstrumentInfo`/`MarketDataPort`
  contracts (reuse only).
- **No user migrations, no DB migrations, no schema changes, no live state machines.**
- **No contract-breaking changes**; new asset-metadata is additive/advisory.
- **No ADR, no code, no tests, no ledger shard in THIS planning step.**

## 6. Execution outline (for the eventual M1.8 code subtrack — not this PR)

0. **M1.8 deep-read** (server-side, ADR-103): read legacy crypto-api asset-catalogue descriptive
   structure + the EMI `SymbolInfo`/`MarketDataPort` seam; propose the asset-metadata shape.
   1. **Duplication Audit** (above). 2. Mock-safe read-only asset-catalogue DTO + assembler
   reusing the symbol asset universe + characterization / contract (frozen `SymbolInfo`/
   `InstrumentInfo`/earn/accounts) / negative fail-closed tests. 3. Append-only IL-shard +
   promotion PR with the canonical 7 sections. Each step server-only; merge operator-gated.
