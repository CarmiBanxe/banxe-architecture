# M1.18 — instruments **breakdown** (by fee-schedule / tick-size) (PLAN, docs-only)

## Status

**PLAN only — no code, no tests, no ADR, no ledger shard in this step.** A read-only **instruments
breakdown** deriving per-`fee_schedule_ref` (and per-`tick_size`) instrument counts from the
existing `list_instruments` source. Mirrors the approved M1.16/M1.17 breakdown pattern. Read-only,
**no live money/APY/balances/fees**.

## Deep-read finding — honest scoping (no fabricated field)

`InstrumentInfo` (the `list_instruments()` element) has exactly **five** fields: `symbol`,
`tick_size` (DecimalStr), `min_qty` (DecimalStr), `max_qty` (DecimalStr), `fee_schedule_ref` (str).
**There is NO `status` and NO `precision` field on `InstrumentInfo`** — `status` /
`price_precision` / `qty_precision` live on the **separate `SymbolInfo`** DTO (symbol universe),
not on the instrument descriptor. The original "per-status / per-precision" candidate framing is
therefore **not derivable from `list_instruments`** without inventing a field — so it is
**explicitly dropped**, not fabricated.

**Real groupable dimensions in `InstrumentInfo`:**
- **`fee_schedule_ref`** — a named categorical (e.g. `spot-default`); the natural primary
  breakdown ("instruments per fee schedule").
- **`tick_size`** — a distinct-value categorical key (config DecimalStr used as a grouping label),
  the secondary breakdown ("instruments per tick size").

`min_qty`/`max_qty` are continuous order-size config and are **not** meaningful grouping keys —
excluded.

## Domain selection (chosen vs alternative)

- **Instruments breakdown — CHOSEN**, scoped to the **real** `InstrumentInfo` dimensions
  (`fee_schedule_ref`, `tick_size`). Pure integer meta counts derived from `list_instruments`,
  reuses the approved M1.16/M1.17 pattern, furthest from money/yield, lowest blast-radius.
- **earn taxonomy↔rates xref — DEFERRED.** Re-surfaces APY-bearing `RateCard` (yield/money-adjacent);
  awaits **explicit operator risk acceptance**.
- **fee-descriptor reference-only / KYC-AML — deferred.**

## 1. Scope

**Legacy area:** none new — M1.18 summarises the existing instrument descriptors by their real
categorical fields. **EMI seam (derive):** new read-only endpoint returning a new derived DTO (e.g.
`InstrumentsBreakdown`): `by_fee_schedule` and `by_tick_size` lists of `InstrumentDimensionCount`
(`key`, `count`) computed from `list_instruments()` by counting `fee_schedule_ref` / `tick_size`,
plus `total` (number of instruments) and `source`. **Path:** to avoid shadowing the existing
`GET /instruments/{symbol}` param route, the endpoint lives on a distinct path — e.g.
`GET /api/v1/catalogue/instruments-breakdown` (catalogue router, alongside the other breakdowns).
The frozen `InstrumentInfo`, `CatalogueMeta`, `CatalogueBreakdown`, `MarketsBreakdown` are **not
modified**; existing endpoints unchanged. The new DTO is a **derived summary**, not a data SoT.
Exact path/shape (incl. whether `by_tick_size` is included) decided in the M1.18 deep-read (step 0).

## 2. Numeric Invariants (I-01)

- The only numerics are **integer meta counts** (per-fee-schedule, per-tick-size, total) — **NOT
  balances, amounts, positions, prices, APY/yields, or computed fees.** `key`/`source` are strings
  (a `tick_size` grouping key is a config label, not a surfaced money amount). No `Decimal`/
  `BigNumber`/`float` money values; **no APY/rate re-surface, no fee computation.**

## 3. Activation Safety

- **Advisory / mock layer ONLY**, a derived read-only summary — **NO live orders, execution,
  balances, positions, payments, fee computation, fund movement; NO infra/secret/PII/ops metrics.**
- No live catalogue/exchange calls, no network/keys, no prod wiring beyond an additive public route;
  default sandbox-mock; **fail-closed** — counts derive from the existing fail-closed
  `list_instruments` (malformed entries already skipped upstream); never a fabricated count, key, or
  dimension.

## 6. Spec-fidelity note (M1.16 lesson)

`InstrumentDimensionCount.key` (a `fee_schedule_ref` value like `spot-default`, or a `tick_size`
value) MUST be specced as a **non-exhaustive `type: string`** with canonical examples in the
description, **never a hard `enum`** — the runtime set grows with `_INSTRUMENT_PARAMS`. (Per the
M1.16 CodeRabbit finding; re-applied in M1.17.)
