## Deep-read finding — why NOT an error-model catalogue (reorientation rationale)

- Advisory endpoints signal errors via the **shared FastAPI `HTTPException`** — `status_code=404`
  in `api/symbols.py` (unknown instrument / unknown instrument-assets, fail-closed) — plus a single
  custom `InstrumentParamsError(KeyError)` (`instruments/params.py`); most advisory endpoints are
  **fail-closed empty-result** (no error raised).
- `HTTPException` is used across **16 routers**, including **live/regulated/auth** ones (`orders`,
  `execution`, `fees`, `quant`, `market_making`, `marketplace`, `auth`, `sandbox*`, `quotes`,
  `risk`, `baas_dss`, `dss`). There is **no dedicated advisory problem-detail / error-DTO** model.
- Therefore an error-model catalogue would either be **marginal** (≈2 real advisory error entries) or
  risk **conflating the shared error mechanism** with an advisory-only surface — failing honest-scope
  (the exact reorientation trigger: *"error-models shared/mixed with live/regulated, or surface not
  deterministic"*). **→ Reorient to the changelog fallback** (guaranteed clean + deterministic).

## 1. Scope

**EMI seam (static changelog, config-as-data):** new read-only endpoint (e.g.
`GET /api/v1/catalogue/changelog`) returning a new derived DTO (e.g. `AdvisorySurfaceChangelog`): an
ordered `entries` list of `ChangelogEntry` (`substep`, `title`), plus `total_entries`, `version`
(**reused `__version__`**), and `source`. The list is an **explicit config-as-data ordered provenance
of the advisory substeps** — **NOT a reflection/scan** of routes/DTOs/exceptions. Path on the
catalogue router, distinct (`/catalogue/*` has no `{param}` route → zero shadow). Frozen DTOs,
`catalogue_meta`, the advisory-surface manifest, and the schema inventory **not modified**. The new
DTO is a **derived summary**, not a data SoT. Exact path/shape decided in the M1.26 deep-read (step 0).

**Distinct from the docs anchor:** this is **runtime build provenance** (which advisory substeps are
published in *this* backend build), config-as-data in the backend — **not** a second copy of the
`docs/migration/M1-advisory-surface-summary.md` planning anchor (arch repo); the two serve different
purposes (runtime provenance vs migration-lane planning) and neither is the other's source.

## 2. Numeric Invariants (I-01)

- The only numeric is the **integer meta count** `total_entries` — **NOT balances, amounts,
  positions, ledger postings, prices, APY/yields, computed fees, uptime, latency, or any infra/ops
  metric.** `substep`/`title`/`version`/`source` are strings. No `Decimal`/`BigNumber`/`float` money
  values; **no balance/posting surface, no fee computation, no observability numerics.**

## 3. Activation Safety

- **Advisory / mock layer ONLY**, a static config-as-data changelog — **NO live orders, execution,
  balances, positions, ledger postings, payments, wallet/custody ops, fund movement; NO live Midaz
  `LedgerPort`/`FeeEnginePort` calls; NO infra/secret/PII/ops/observability metrics; NO live error
  injection.**
- **No reflection/scan** (of routes, DTOs, or exceptions — which would risk capturing live/regulated/
  auth surfaces); no network/keys, no prod wiring beyond an additive public route; default
  sandbox-mock; **fail-closed** — the changelog is a fixed curated list; never reflects a
  non-advisory substep; never fabricates an entry.
