## Why this domain (mapping rationale)

Per `docs/migration/banxe_to_emi_mapping.md`, the earn/DSE-advisory slice is the P0
lowest-blast-radius lane and is where M1.1–M1.3 already landed. The adjacent un-mapped
crypto slices (`crypto-api` wrap, payments rewrite) are **higher blast radius** (new EMI seam
/ P0 regulated rails) and are deferred. M1.4 stays in the earn vertical — the same seam, the
same mock-safe advisory pattern — completing the **descriptive** coverage of the legacy earn
product (M1.3 = fees/rates/product fields; **M1.4 = lifecycle status taxonomy**) **without**
touching the live transaction execution (which M1.1 fixed as operator-gated).

## 2. Numeric invariants (I-01)

- The status taxonomy is **non-numeric** (enum labels), so no money crosses the seam from
  the enums themselves.
- **If** any numeric is surfaced alongside (e.g. a step amount / count), it MUST be
  `Decimal` / `DecimalString` via the existing `normalize_decimal` (M1.2/M1.3) — **no
  `BigNumber`, no `float` outward**, fail-closed on non-numeric. No parallel money type.

## 3. Activation Safety

- **Mock / advisory wiring ONLY.** Deterministic descriptive metadata; **no live earn
  transaction execution** (invest / withdraw / FIAT_SENDING / EXCHANGING steps stay
  **operator-gated**, as fixed in M1.1 — FastExchange / ABS / RabbitMQ are out-of-scope).
- **No prod / live coupling, no hidden feature-flag activation path.** Default provider stays
  `"mock"`; any new selectable variant is non-default and fail-closed for non-wired names.
- **fail-closed** for unactivated configs / missing earn products (reuse the M1.2/M1.3 seam
  posture: non-wired → `ValueError(... operator-gated ...)`).

## 4. Duplication Audit (ADR-102) — MANDATORY before any M1.4 code

Before touching code, a repo-wide Duplication Audit is **required** (no delete/merge without
it):
1. Repo-wide search for existing status / state / enum / lifecycle representations — in
   `dse/`, `earn/`, `models.py`, any state-machine, plus DTOs, fixtures, adapters, docs.
2. Identify the **source-of-truth** (legacy enums above) and **every consumer** of the earn
   seam (already known: `app.py`, `dse/engine.py`, `EarnMetrics` contract — confirm at audit
   time).
3. No delete / merge until hidden consumers are confirmed.
4. Attach a "Duplication Audit" section to the M1.4 PR (matches → keep / merge / delete +
   risks).
5. Doubt → fail-closed + escalate to human.
