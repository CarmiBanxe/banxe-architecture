**No new legacy domain, no new external seam, no live balances/positions.**

## Why this domain (mapping rationale)

Per `docs/migration/banxe_to_emi_mapping.md`, the earn/DSE-advisory slice is the P0
lowest-blast-radius lane where M1.1–M1.5 landed. M1.6 stays inside it: it does **not** open a
new legacy module — it **aggregates the M1.2–M1.5 outputs** into a read-only advisory statement
(the legacy `money-info` / `position-balance` / earn-product summary *shape*, mock values). The
adjacent P0/P1 slices — payments (regulated), `crypto-api` wrap, wallets/Midaz, KYC/AML — are
**higher blast radius** and remain deferred.

## 1. Scope

**Legacy reference (shape only, snapshot `banxe-crypto-earn`):** the read-only summary DTOs noted
in the M1.1 deep-read — `money-info`, `position-balance`, `get-earn-fee`, positions/product
summary — i.e. the **descriptive per-asset/product earn statement** (yield + fee structure +
lifecycle status + risk band). **Values stay mock**; only the *statement shape* is traced.

**EMI target (reuse + small additive):** compose the existing advisory outputs into a read-only
**earn advisory statement** —
- `earn/rates.py` `EarnRatesResponse` / `RateCard` (rates + risk_band, read-only comparison),
- `earn/crypto_earn.py` `EarnMetrics` (yield + fee/product in `risk_summary`),
- `earn/status.py` `EarnAdvisoryStatus` (M1.4) + the M1.5 analytics `advisory_status`.

The exact statement DTO/shape and whether it extends `EarnRatesResponse` or adds a sibling
read-only summary is decided in the **M1.6 deep-read (step 0)**, not here. **Prefer keeping
`EarnMetrics` / `AnalyticsContext` contracts unchanged**; any new statement type is additive,
read-only, advisory.

## 2. Numeric Invariants (I-01)

- Every numeric in the statement (yield, fees, minimal amounts, any aggregate) MUST be
  `Decimal` / `DecimalString` via the existing `normalize_decimal` (M1.2/M1.3) — **no
  `BigNumber`, no `float` outward**, fail-closed on non-numeric. No parallel money type, no new
  rounding rule beyond the established 4dp DecimalStr.

## 3. Activation Safety

- **Advisory / mock layer ONLY** — a descriptive read-only statement, **not** live balances,
  **not** real positions, **not** execution. No invest/withdraw/payout, no payments, no fund
  movement, no FastExchange/ABS/RabbitMQ coupling.
- **No live data:** deterministic mock composition of already-migrated advisory values.
- **No prod wiring change, no feature-flag bypass, no network/keys, no crypto-wallet/crypto-api
  seam.** Default earn provider stays `"mock"`; fail-closed for non-wired/unsupported inputs.

## 4. Duplication Audit (ADR-102) — MANDATORY before any M1.6 code

Repo-wide Duplication Audit is **required** before touching code (no delete/merge without it):
1. Search for existing statement / summary / report / response representations — esp.
   `earn/rates.py` (`EarnRatesResponse`), `dse/` analytics, any earn summary DTO.
2. Confirm **reuse** of `EarnMetrics` + `EarnAdvisoryStatus` + `RateCard`/`RiskBand` as inputs —
   **do not duplicate** rate/status/risk sources (single source-of-truth preserved); **no second
   statement SoT**.
3. Identify the source-of-truth + every consumer of the touched seam; no parallel statement path.
4. Attach a "Duplication Audit" section to the M1.6 PR (keep / merge / delete + risks).
5. Doubt → fail-closed + escalate to human.
