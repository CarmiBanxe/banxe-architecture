## Status

**PLAN only — no code, no tests, no ADR, no ledger shard in this step.** The first **list-valued
flattened** breakdown: per-blockchain-`network` asset counts, derived by flattening
`CryptoAssetMetadata.networks` over the M1.8 asset catalogue. Mirrors the M1.16–M1.20 breakdown
pattern but over a list field (flatten → per-element count). Read-only, **no live money/balances/
postings/fees** — `networks` are pure descriptive infra labels.

## 1. Scope

**Legacy area:** none new — M1.21 summarises the existing asset catalogue by blockchain network.
**EMI seam (derive, flatten):** new read-only endpoint (e.g. `GET /api/v1/catalogue/network-breakdown`)
returning a new derived DTO (e.g. `NetworkBreakdown`): a `by_network` list of `NetworkCount`
(`network`, `count`) computed by flattening `asset_catalog(market_data).assets[*].networks` and
counting assets per network, plus `total_assets` (catalogue size) and `source`.

**Flatten semantics (documented honestly):** one asset on N networks contributes to N buckets; an
asset with an **empty** `networks` list (e.g. fiat) contributes to **no** bucket. Therefore
`sum(by_network counts)` = total network memberships, which **need not equal** `total_assets`. The
DTO surfaces `total_assets` (denominator) and the `by_network` counts; a `total_memberships`
(= sum) MAY be added in the code-step for clarity. Path placed on the catalogue router alongside the
other breakdowns; zero shadow risk (`/catalogue/*` has no `{param}` route). The frozen
`CryptoAssetMetadata`, `AssetCatalogResponse` and all breakdown DTOs are **not modified**; existing
endpoints unchanged. The new DTO is a **derived summary**, not a data SoT. Exact path/shape decided
in the M1.21 deep-read (step 0).

## 2. Numeric Invariants (I-01)

- The only numerics are **integer meta counts** (per-network asset count, total_assets,
  total_memberships) — **NOT balances, amounts, positions, ledger postings, prices, APY/yields, or
  computed fees.** `network`/`source` are strings (a network is a descriptive label). No `Decimal`/
  `BigNumber`/`float` money values; **no balance/posting surface, no fee computation.**

## 3. Activation Safety

- **Advisory / mock layer ONLY**, a derived read-only flatten summary — **NO live orders, execution,
  balances, positions, ledger postings, payments, wallet/custody ops, fund movement; NO live Midaz
  `LedgerPort`/`FeeEnginePort` calls; NO infra/secret/PII/ops metrics.**
- No live catalogue/exchange calls, no network/keys, no prod wiring beyond an additive public route;
  default sandbox-mock; **fail-closed** — counts derive from the existing fail-closed `asset_catalog`
  (malformed entries already skipped upstream); never a fabricated network or count.

## 6. Spec-fidelity note (M1.16 lesson)

`NetworkCount.network` (a network label like `bitcoin` / `ethereum`) MUST be specced as a
**non-exhaustive `type: string`** with canonical examples in the description, **never a hard
`enum`** — the runtime set grows with the asset-catalogue config. (Per the M1.16 CodeRabbit finding;
re-applied in M1.17–M1.20.)
