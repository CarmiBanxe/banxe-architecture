# M1.11 — instrument ↔ asset **cross-reference advisory view** (PLAN, docs-only)

<!-- Source: docs/migration/M1.11-instrument-asset-xref.md | Date: 2026-06-18 | Lane: BANXE.RAR → EMI | Server-only (ADR-103) -->

## Status

**PLAN only — no code, no tests, no ADR, no ledger shard in this step.** Next
lowest-blast-radius **advisory** subtrack after M1.10 (instruments list), **not greenfield**. A
read-only **composition view** linking a trading symbol's instrument parameters (M1.9
`InstrumentInfo`) with the metadata of its **base/quote assets** (M1.8 `CryptoAssetMetadata`) —
reusing the existing single sources and `split_symbol`. Read-only, **no live money/orders/
balances/fees**. Chosen over enriching the **frozen** `SymbolInfo` (contract risk) and over the
fee-descriptor / KYC-AML (deferred).

## Why this domain (mapping rationale + deep-read)

Deep-read: assets (`assets/catalog.py`: `CryptoAssetMetadata` + `_ASSET_META`), instruments
(`instruments/params.py`: `InstrumentInfo` + `_INSTRUMENT_PARAMS`), and symbols (`SymbolInfo` +
`MarketDataPort`, `split_symbol`) are already migrated and frozen. There is **no view that ties
an instrument to its assets**. M1.11 simply **composes** these existing sources into one
read-only cross-reference — the smallest additive step, zero new data, zero money semantics,
**no change to any frozen contract**.

## 1. Scope

**Legacy area:** none new — M1.11 composes the M1.8 asset metadata + M1.9 instrument params for a
symbol. **EMI seam (compose):** add a read-only endpoint (e.g. `GET /api/v1/instruments/{symbol}/assets`)
returning a **new composition view DTO** (e.g. `InstrumentAssetView` = the symbol's `InstrumentInfo`
+ its base/quote `CryptoAssetMetadata`), assembled by reusing `split_symbol` + `instrument_info`
+ the M1.8 asset metadata (`_ASSET_META`/`asset_catalog`). Existing `GET /instruments`,
`/instruments/{symbol}`, `/symbols`, `/assets/metadata` unchanged. The composition DTO is a
**view over existing DTOs**, not a new catalogue/registry/SoT. Exact shape decided in the M1.11
deep-read (step 0).

## 2. Numeric Invariants (I-01)

- All numerics are the existing fields: instrument `tick_size`/`min_qty`/`max_qty` (`DecimalString`
  trading params) + asset `display_decimals` (int). **NOT balances, amounts, positions, or
  computed fees.** No `BigNumber`/`float`; **no fee computation** (`FeeEnginePort` owns it; only
  the `fee_schedule_ref` string is carried via `InstrumentInfo`).

## 3. Activation Safety

- **Advisory / mock layer ONLY**, a read-only composition — **NO live orders, execution,
  balances, positions, payments, fee computation, or fund movement.**
- No live catalogue/exchange calls, no network/keys, no prod wiring beyond an additive route;
  default sandbox-mock; **fail-closed** — unknown symbol → 404; a missing asset descriptor falls
  back to the existing deterministic default (never fabricated balance/price data).

## 4. Duplication Audit (ADR-102) — MANDATORY before any M1.11 code

1. Repo-wide search for instrument/asset/symbol cross-reference or join views — esp.
   `assets/catalog.py` (`CryptoAssetMetadata`/`_ASSET_META`/`asset_catalog`), `instruments/params.py`
   (`InstrumentInfo`/`_INSTRUMENT_PARAMS`/`instrument_info`), `models.py` (`SymbolInfo`/`split_symbol`),
   `api/symbols.py`, `api/assets.py`.
2. **Canonical SoTs (reuse, do NOT duplicate):** asset metadata = `assets/catalog.py` (`_ASSET_META`);
   instrument params = `instruments/params.py` (`_INSTRUMENT_PARAMS`); symbol universe =
   `SymbolInfo`/`MarketDataPort`. M1.11 **composes** them — **no second catalogue, registry, or
   params table**; the new view DTO is a composition over existing DTOs (like `AnalyticsContext`),
   not a new data source.
3. **`FeeEnginePort` = fee SoT** — not touched/duplicated.
4. Source-of-truth + every consumer; keep/merge/delete + risks; doubt → fail-closed + escalate.

### Frozen contracts (must not break)
`SymbolInfo`, `InstrumentInfo`, `MarketDataPort`, `FeeEnginePort`, and the M1.6–M1.10 contracts
(`EarnMetrics`, `AnalyticsContext`, `EarnRatesResponse`, earn statement, accounts metadata,
`CryptoAssetMetadata`/`AssetCatalogResponse`, `_INSTRUMENT_PARAMS`/`instrument_info`/`list_instruments`).

## 5. Out-of-scope (strictly NOT in M1.11)

- **All P0 / regulated / live parts:** live orders, execution, balances, positions, payments,
  fund movement, live catalogue/exchange operations.
- **Fee computation / billing / preview** (`FeeEnginePort`/`/fees/preview`); only `fee_schedule_ref`.
- **KYC/AML**, cards, crypto-wallet ops.
- **No enrichment of the frozen `SymbolInfo`** (no new SymbolInfo fields); **no new catalogue/
  registry/params**; the composition is a view only.
- **No user migrations, no DB migrations, no schema changes, no live state machines.**
- **No contract-breaking changes**; the cross-reference view is additive over existing DTOs.
- **No ADR, no code, no tests, no ledger shard in THIS planning step.**
