## Correction to M0/M1.0

M0/M1.0 reported "money intersection = 0" for crypto-earn — that was an **index-only
(path-name)** read. **Content read corrects it: the module uses `bignumber.js` heavily** (26
files; entities store money as `BigNumber`). The Decimal/I-01 gap is therefore a
**bignumber.js → `Decimal` conversion**, not "add Decimal from scratch".

## 2. Amount/rate/fee fields + types (Decimal/I-01 gap)

All money is `BigNumber` over a TypeORM `type: 'decimal'` column via `BigNumberFieldTransformer`
(DB precision preserved; TS uses bignumber.js):

| Entity | Field | DB type | TS type |
|---|---|---|---|
| earn-transaction | `amount`, `amountInUsdt?`, `fee` | decimal | **BigNumber** |
| earn-config | `minimalAmountInUsdt`, `investmentFeePercentage`, `minimalInvestmentFeeInUsdt`, `withdrawalFeeInUsdt`, `cryptoEarnWithdrawalFeePercentage`, `quickswapFeePercentage` | decimal | **BigNumber** |
| earn-transaction | `withdrawal_percent` | decimal | BigNumber |

**Gap:** EMI mandates Python `Decimal` + `DecimalString` on the wire (I-01/I-05). Conversion =
bignumber.js → Decimal (semantically equivalent arbitrary-precision decimal). DB columns are
already `decimal` → no precision loss in migration.

## 3. Live-provider coupling (operator-gated; OUT of M1 scope)

- **FastExchange GraphQL** (`earn/graphql/apollo-client/fast-exchange-{queries,mutations}.ts`):
  `getExchangeComission` / `prepareExchange` → exchange commission + multiplier. The earn flow
  depends on FastExchange for conversion/rates.
- **ABS / virtual-abs** (`config/virtual-abs-client.config.ts`): coupling to the fiat/identity
  backend (accounts).
- **RabbitMQ** (`config/rabbit-mq.config.ts`) + **gRPC** (`config/grpc-server.config.ts`) +
  1 microservice `@MessagePattern`/`ClientProxy` → event/message mesh.
- No `@Cron`/`@OnEvent`/HttpService/axios; no literal keys/URLs found in source (config-driven).

These are **live execution / external providers → operator-gated, NOT M1** (M1 is the advisory
wrap only).

## 4. EarnPort contract mapping (in-scope advisory vs out-of-scope live)

**In-scope (M1 advisory wrap → maps onto the EXISTING EMI earn-rates seam):**
- `earn-config` rate/fee fields (investment fee %, minimal amounts, withdrawal fee %, quickswap
  fee %) → EMI **EarnMetrics** advisory shape (apy/rate/fee/protocol/chain/lockup).
- product/position **read** (positions, position-balance, get-products) → advisory rate/position
  preview (DecimalString, no execution).

**Out-of-scope (live; operator-gated — NOT M1):**
- `invest` / `withdraw` / `start-earn-*` (execution), FastExchange `prepareExchange` (live
  exchange), ABS account moves, RabbitMQ side effects, 2FA. These stay behind the operator-gated
  go-live track (no live activation in the advisory wrap).

## Duplication Audit (ADR-102)

Coverage: scanned the **live EMI backend** `banxe-trading-backend@main` (`src/banxe_trading_backend/**`,
greps for `Earn*`, `earn_rates`, `/earn/rates`, providers/config) AND the legacy
`banxe-crypto-earn/src` (entities/services/dtos).

- **The EMI earn-rates advisory seam ALREADY EXISTS (source-of-truth):** `earn/providers.py`,
  `earn/rates.py`, classes `EarnRatesCatalog` / `EarnRatesProvider` / `EarnRatesResponse` /
  `EarnMetrics` / `EarnAlternative`; endpoints `/api/v1/earn/rates` (internal) + `/v1/earn/rates`
  (BaaS); config seams `earn_rates_provider="mock"` + `dse_earn_provider="mock"` (mock-default,
  fail-closed); advisory fields apy/rate/protocol/chain/lockup/yield; wired into the DSE engine.
- **Consumers:** the DSE engine (`dse/engine.py`, `dse/provider_layer.py`), `api/earn.py`, the
  BaaS facade, and the sandbox/DSE earn provider.
- **Verdict: DO NOT build a new earn module / DO NOT re-implement earn-rates.** M1 = a new
  **mock `EarnRatesProvider` variant** that surfaces the legacy crypto-earn products/config as
  **advisory rates** behind the existing `earn_rates_provider` seam — **extend/wrap**, not
  duplicate. The legacy NestJS earn service itself is NOT ported (its live half is out-of-scope).
- **Fail-closed / escalate:** any attempt to port invest/withdraw/FastExchange = scope breach →
  blocked; surface to operator.
