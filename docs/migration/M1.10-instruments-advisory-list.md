# M1.10 — instruments **advisory list/catalogue** endpoint (PLAN, docs-only)

<!-- Source: docs/migration/M1.10-instruments-advisory-list.md | Date: 2026-06-18 | Lane: BANXE.RAR → EMI | Server-only (ADR-103) -->

## Status

**PLAN only — no code, no tests, no ADR, no ledger shard in this step.** Next
lowest-blast-radius **advisory** subtrack after M1.9 (instrument params), **not greenfield**. A
minimal additive **read-only `GET /instruments` list/catalogue** that surfaces the
already-migrated per-symbol advisory instrument parameters (M1.9 `_INSTRUMENT_PARAMS`) as a
collection — reusing the existing `InstrumentInfo` DTO + the M1.9 single source. Read-only,
**no live money/orders/balances/fees**. Chosen over the fee-schedule descriptor (which risks
duplicating `FeeEnginePort` and is fee/money-adjacent) and over KYC/AML (compliance gate, deferred).

## Why this domain (mapping rationale + deep-read)

Deep-read: `api/symbols.py` exposes `GET /symbols` (list) and `GET /instruments/{symbol}`
(single, M1.9 config-driven) — but **no `GET /instruments` list**. M1.9 `instruments/params.py`
already holds the per-symbol catalogue (`_INSTRUMENT_PARAMS`) + `instrument_info()`. M1.10 simply
**lists** that existing catalogue — the smallest possible additive step, fully inside the
already-migrated instrument seam, with zero new data and zero money semantics.

## 1. Scope

**Legacy area:** none new — M1.10 surfaces the existing M1.9 advisory instrument catalogue as a
list. **EMI seam (extend in place):** add `GET /instruments` → `list[InstrumentInfo]`, assembled
from the M1.9 `_INSTRUMENT_PARAMS` single source (a small `list_instruments()` reusing
`instrument_info`); existing `GET /instruments/{symbol}` and `GET /symbols` unchanged.
`InstrumentInfo` DTO stays **frozen** (reused; no new DTO). The exact assembler signature is
decided in the M1.10 deep-read (step 0).

## 2. Numeric Invariants (I-01)

- The listed fields are the existing `InstrumentInfo` ones: `tick_size`/`min_qty`/`max_qty` as
  `DecimalString` **trading-parameter config** (granularity & order-size limits) — **NOT
  balances, live amounts, positions, or computed fees**; `fee_schedule_ref` is a string
  reference. No `BigNumber`/`float`; **no fee computation** (that is `FeeEnginePort`).

## 3. Activation Safety

- **Advisory / mock layer ONLY**, config-as-data list — **NO live orders, execution, balances,
  positions, payments, fee computation, or fund movement.**
- No live catalogue/exchange calls, no network/keys, no prod wiring beyond an additive route;
  default sandbox-mock; **fail-closed** (deterministic from the config; empty/consistent if the
  source is unavailable — never a fabricated entry).

## 4. Duplication Audit (ADR-102) — MANDATORY before any M1.10 code

1. Repo-wide search for instrument list/catalogue endpoints & assemblers — esp. `api/symbols.py`
   (`/symbols`, `/instruments/{symbol}`), `instruments/params.py` (`_INSTRUMENT_PARAMS`,
   `instrument_info`), `models.py` (`InstrumentInfo`/`SymbolInfo`).
2. **Canonical instrument SoT = `InstrumentInfo` + `instruments/params.py` (M1.9 `_INSTRUMENT_PARAMS`)
   + symbols seam** (real upstream = ADR-021 TODO). M1.10 **lists/reuses** that single source — it
   must **not** create a second instrument catalogue, a second `_INSTRUMENT_PARAMS`, or a new DTO.
3. **`FeeEnginePort` = canonical fee-computation SoT** — M1.10 only carries the existing
   `fee_schedule_ref` string via `InstrumentInfo`; **no fee math, no duplication**.
4. Source-of-truth + every consumer; keep/merge/delete + risks; doubt → fail-closed + escalate.

### Frozen contracts (must not break)
`InstrumentInfo`, `SymbolInfo`, `MarketDataPort`, `FeeEnginePort`, and the M1.6–M1.9 contracts
(`EarnMetrics`, `AnalyticsContext`, `EarnRatesResponse`, earn statement, accounts metadata,
`CryptoAssetMetadata`/`AssetCatalogResponse`, `instrument_info`/`_INSTRUMENT_PARAMS` shape).

## 5. Out-of-scope (strictly NOT in M1.10)

- **All P0 / regulated / live parts:** live orders, execution, balances, positions, payments,
  fund movement, live catalogue/exchange operations.
- **Fee computation / billing / preview** (owned by `FeeEnginePort`/`/fees/preview`); M1.10 only
  lists the `fee_schedule_ref` string carried by `InstrumentInfo`.
- **KYC/AML**, cards, crypto-wallet ops.
- **No new instrument DTO or second catalogue/`_INSTRUMENT_PARAMS`.**
- **No user migrations, no DB migrations, no schema changes, no live state machines.**
- **No contract-breaking changes** to `InstrumentInfo`/`SymbolInfo`/`MarketDataPort`/`FeeEnginePort`.
- **No ADR, no code, no tests, no ledger shard in THIS planning step.**
