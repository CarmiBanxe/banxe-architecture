# M1.19 — symbols **breakdown** (by status / precision) (PLAN, docs-only)

<!-- Source: docs/migration/M1.19-symbols-breakdown.md | Date: 2026-06-18 | Lane: BANXE.RAR → EMI | Server-only (ADR-103) -->

## Status

**PLAN only — no code, no tests, no ADR, no ledger shard in this step.** A read-only **symbols
breakdown** deriving per-`status` and per-`price_precision`/`qty_precision` symbol counts from the
existing `MarketDataPort.list_symbols()` source. Mirrors the approved M1.16/M1.17/M1.18 breakdown
pattern. Read-only, **no live money/APY/balances/fees**. These are exactly the `status`/`precision`
dimensions that M1.18 honestly **excluded** from instruments (they are not on `InstrumentInfo`) —
they **do** exist on `SymbolInfo`, so the symbols breakdown is a real, non-fabricated domain.

## Deep-read finding — confirmed real dimensions (no fabricated field)

`SymbolInfo` (the `MarketDataPort.list_symbols()` element) has exactly **six** fields:
`symbol: str`, `base_asset: str`, `quote_asset: str`, `price_precision: int`, `qty_precision: int`,
`status: str`. Mock universe values: `status="trading"`, `price_precision=2`, `qty_precision=4`.

**Real groupable dimensions for M1.19:**
- **`status`** (str categorical, e.g. `trading`) — primary.
- **`price_precision`** (int) and **`qty_precision`** (int) — distinct-value categorical keys
  (the precision *value* used as a grouping label, not a surfaced numeric).

`base_asset`/`quote_asset` are **excluded** — already covered by the M1.17 markets breakdown
(per-base/per-quote); M1.19 does **not** duplicate them. No fabricated field.

## Domain selection (chosen vs alternatives)

- **Symbols breakdown — CHOSEN**, scoped to the **real** `SymbolInfo` dimensions (`status`,
  `price_precision`, `qty_precision`). Pure integer meta counts from `list_symbols`, reuses the
  approved M1.16–M1.18 pattern, furthest from money/yield.
- **earn taxonomy↔rates xref — DEFERRED.** Re-surfaces APY-bearing `RateCard` (yield/money-adjacent);
  awaits **explicit operator risk acceptance**.
- **M1 summary-refresh — NOT now.** The canonical anchor is current to M1.17; re-refreshing for a
  single M1.18 delta is low-value churn — better deliver a new advisory domain and batch the summary
  refresh after several substeps (established rhythm).
- **fee-descriptor reference-only / KYC-AML — deferred.**

## 1. Scope

**Legacy area:** none new — M1.19 summarises the existing symbol universe by its real categorical
fields. **EMI seam (derive):** new read-only endpoint (e.g. `GET /api/v1/catalogue/symbols-breakdown`)
returning a new derived DTO (e.g. `SymbolsBreakdown`): `by_status`, `by_price_precision`,
`by_qty_precision` lists of `SymbolDimensionCount` (`key`, `count`) computed from
`MarketDataPort.list_symbols()` by counting `status` / `price_precision` / `qty_precision`, plus
`total` (number of symbols) and `source`. **Path:** placed on the catalogue router alongside the
other breakdowns (`/catalogue/breakdown`, `/catalogue/instruments-breakdown`) — a distinct path with
zero shadow risk (`/symbols` is exact, no `{param}` route). The frozen `SymbolInfo`, `MarketDataPort`,
`CatalogueMeta`, `CatalogueBreakdown`, `MarketsBreakdown`, `InstrumentsBreakdown` are **not modified**;
existing endpoints unchanged. The new DTO is a **derived summary**, not a data SoT. Exact path/shape
decided in the M1.19 deep-read (step 0).

## 2. Numeric Invariants (I-01)

- The only numerics are **integer meta counts** (per-status, per-precision, total) — **NOT balances,
  amounts, positions, prices, APY/yields, or computed fees.** `key`/`source` are strings; a
  `price_precision`/`qty_precision` grouping key is a **config label** (the precision value
  stringified), **not** a surfaced numeric live-value. No `Decimal`/`BigNumber`/`float` money values;
  **no APY/rate re-surface, no fee computation.**

## 3. Activation Safety

- **Advisory / mock layer ONLY**, a derived read-only summary — **NO live orders, execution,
  balances, positions, payments, fee computation, fund movement; NO infra/secret/PII/ops metrics.**
- No live catalogue/exchange calls, no network/keys, no prod wiring beyond an additive public route;
  default sandbox-mock; **fail-closed** — counts derive from the existing `list_symbols` (deterministic
  mock universe); never a fabricated count, key, or dimension.

## 6. Spec-fidelity note (M1.16 lesson)

`SymbolDimensionCount.key` (a `status` value like `trading`, or a stringified precision like `2`)
MUST be specced as a **non-exhaustive `type: string`** with canonical examples in the description,
**never a hard `enum`** — the runtime set grows with the symbol universe. (Per the M1.16 CodeRabbit
finding; re-applied in M1.17/M1.18.)
