# M1.12 — markets **advisory bundle** (instrument↔asset xref list) (PLAN, docs-only)

<!-- Source: docs/migration/M1.12-markets-advisory-bundle.md | Date: 2026-06-18 | Lane: BANXE.RAR → EMI | Server-only (ADR-103) -->

## Status

**PLAN only — no code, no tests, no ADR, no ledger shard in this step.** Next lowest-blast-radius
**advisory** subtrack after M1.11 (single instrument↔asset xref), **not greenfield**. A read-only
**list-bundle over the existing M1.11 single xref**: `GET /api/v1/markets` →
`list[InstrumentAssetXref]`, one entry per configured instrument (instrument params + its base/quote
asset metadata). Read-only, **no live money/orders/balances/fees**. Chosen over the
asset→instruments reverse-xref (introduces new filter semantics) and over the fee-descriptor /
KYC-AML (deferred).

## Why this domain (mapping rationale + deep-read)

Deep-read: M1.11 already provides the single-symbol composition `instrument_asset_xref(symbol)` →
`InstrumentAssetXref`, and M1.10 established the list pattern `list_instruments()` over
`_INSTRUMENT_PARAMS`. There is **no list/bundle of the cross-reference**. M1.12 simply iterates the
existing catalogue and reuses the M1.11 assembler — the smallest additive step, zero new data, zero
money semantics, **no new DTO** (reuses `InstrumentAssetXref`).

## 1. Scope

**Legacy area:** none new — M1.12 lists the M1.11 composition across the instrument universe.
**EMI seam (compose-list):** new read-only endpoint `GET /api/v1/markets` →
`list[InstrumentAssetXref]`, assembled by a new `list_instrument_asset_xref()` that iterates the
configured symbols (`_INSTRUMENT_PARAMS`, sorted, like `list_instruments()`) and reuses
`instrument_asset_xref(symbol)`. A distinct path (`/markets`) is used to avoid ambiguity with
`/instruments/{symbol}`. Existing `/symbols`, `/instruments`, `/instruments/{symbol}`,
`/instruments/{symbol}/assets`, `/assets/metadata` unchanged. **Reuses `InstrumentAssetXref` —
no new DTO/catalogue/registry.** Exact path/shape decided in the M1.12 deep-read (step 0).

## 2. Numeric Invariants (I-01)

- Only existing fields are surfaced (via `InstrumentAssetXref`): instrument `tick_size`/`min_qty`/
  `max_qty` (`DecimalString` trading params) + asset `display_decimals` (int). **NOT balances,
  amounts, positions, or computed fees.** No `BigNumber`/`float`; **no fee computation**
  (`FeeEnginePort` owns it; only the `fee_schedule_ref` string is carried).

## 3. Activation Safety

- **Advisory / mock layer ONLY**, a read-only list composition — **NO live orders, execution,
  balances, positions, payments, fee computation, or fund movement.**
- No live catalogue/exchange calls, no network/keys, no prod wiring beyond an additive route;
  default sandbox-mock; **fail-closed** — a malformed/unresolvable catalogue entry is skipped
  (like `list_instruments`), never a fabricated market.

## 4. Duplication Audit (ADR-102) — MANDATORY before any M1.12 code

1. Repo-wide search for any markets/bundle/xref-list endpoint or assembler — esp.
   `instruments/xref.py` (`InstrumentAssetXref`/`instrument_asset_xref`), `instruments/params.py`
   (`_INSTRUMENT_PARAMS`/`list_instruments`), `assets/catalog.py` (`asset_metadata`/`_ASSET_META`),
   `models.py` (`SymbolInfo`/`split_symbol`), `api/symbols.py`.
2. **Canonical SoTs (reuse, do NOT duplicate):** instrument params = `_INSTRUMENT_PARAMS`/
   `instrument_info`; asset metadata = `_ASSET_META`/`asset_metadata`; symbol universe =
   `SymbolInfo`/`MarketDataPort`; single composition = `InstrumentAssetXref`/`instrument_asset_xref`.
   M1.12 **lists/composes** them — **no second catalogue, registry, params table, or DTO**; it
   reuses `InstrumentAssetXref` (the bundle entry).
3. **`FeeEnginePort` = fee SoT** — not touched/duplicated.
4. Source-of-truth + every consumer; keep/merge/delete + risks; doubt → fail-closed + escalate.

### Frozen contracts (must not break)
`SymbolInfo`, `InstrumentInfo`, `MarketDataPort`, `FeeEnginePort`, `CryptoAssetMetadata`,

## 5. Out-of-scope (strictly NOT in M1.12)

- **All P0 / regulated / live parts:** live orders, execution, balances, positions, payments,
  fund movement, live catalogue/exchange operations.
- **Fee computation / billing / preview** (`FeeEnginePort`/`/fees/preview`); only `fee_schedule_ref`.
- **KYC/AML**, cards, crypto-wallet ops.
- **No new DTO** (reuse `InstrumentAssetXref`); **no new catalogue/registry/params**; **no
  enrichment of frozen `SymbolInfo`/`InstrumentInfo`/`CryptoAssetMetadata`**.
- **No user migrations, no DB migrations, no schema changes, no live state machines.**
- **No contract-breaking changes**; the bundle is an additive list over existing composition.
- **No ADR, no code, no tests, no ledger shard in THIS planning step.**
