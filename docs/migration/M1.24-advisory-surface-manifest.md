## Deep-read finding — why a STATIC manifest, not programmatic route enumeration

`create_app()` mounts **many** routers: advisory M-track ones (earn, accounts, assets, symbols,
catalogue) **and** live/regulated or infra ones — `orders`, `execution`, `fees`, `quant`,
`market_making`, `marketplace`, `sandbox*`, `baas_dss`, and **`internal`** (mounted with
`include_in_schema=False`, `prefix="/internal"`, exposing `/internal/health/dse-baas` +
`/internal/metrics/dse-baas`), plus an infra `/healthz`. **Programmatically enumerating `app.routes`
would leak live/regulated and infra/observability endpoints into an advisory snapshot** — a fence
violation. The existing `api/catalogue.py` docstring already records the rule: *"Does NOT touch or
expose the internal observability endpoints (/internal/\*), which stay infra-fenced."*

**Honest scope decision (no fabrication):** M1.24 is an **explicit, curated config-as-data list of
the advisory read-only families only** (earn / accounts / assets / symbols·instruments·markets /
catalogue meta+breakdowns), **never a programmatic route scan**, and it **explicitly excludes**
`/internal/*`, `/healthz`, `orders`, `execution`, `fees`, `quant`, `market_making`, `marketplace`,
`sandbox*`, `baas_dss`. The manifest enumerates only what the M-track has already published as
advisory read-only surface.

## 1. Scope

**EMI seam (static manifest, config-as-data):** new read-only endpoint (e.g.
`GET /api/v1/catalogue/advisory-surface`) returning a new derived DTO (e.g.
`AdvisorySurfaceManifest`): a `families` list of `AdvisorySurfaceFamily` (`family`,
`endpoint_count`), plus `total_families`, `total_endpoints`, `version` (**reused `__version__`**),
and `source`. The list is an **explicit config-as-data inventory of the advisory read-only families**
— **NOT a programmatic `app.routes` scan** (which would leak live/regulated + `/internal/*` + infra
surfaces). Path on the catalogue router, distinct (`/catalogue/*` has no `{param}` route → zero
shadow). Frozen DTOs, `catalogue_meta`, and existing endpoints **not modified**. The new DTO is a
**derived summary**, not a data SoT. Exact path/shape decided in the M1.24 deep-read (step 0).

**Explicit exclusion:** `/internal/*`, `/healthz`, and any live/regulated/sandbox/baas surface are
**never** listed.

## 2. Numeric Invariants (I-01)

- The only numerics are **integer meta counts** (endpoint_count, total_families, total_endpoints) —
  **NOT balances, amounts, positions, ledger postings, prices, APY/yields, computed fees, uptime,
  latency, request rates, or any infra/ops metric.** `family`/`version`/`source` are strings. No
  `Decimal`/`BigNumber`/`float` money values; **no balance/posting surface, no fee computation, no
  health-of-services/observability numerics.**

## 3. Activation Safety

- **Advisory / mock layer ONLY**, a static config-as-data manifest — **NO live orders, execution,
  balances, positions, ledger postings, payments, wallet/custody ops, fund movement; NO live Midaz
  `LedgerPort`/`FeeEnginePort` calls; NO infra/secret/PII/ops/observability metrics; NO uptime/
  health-of-services exposure.**
- **No programmatic route enumeration** (fence against leaking `/internal/*`, live/regulated, sandbox
  surfaces); no network/keys, no prod wiring beyond an additive public route; default sandbox-mock;
  **fail-closed** — the manifest is a fixed curated list; never reflects a non-advisory or infra
  endpoint; never fabricates a family.

- **No ADR, no code, no tests, no ledger shard in THIS planning step.**

## 6. Spec-fidelity note (M1.16 lesson)

`AdvisorySurfaceFamily.family` (a family label like `earn` / `catalogue`) MUST be specced as a
**non-exhaustive `type: string`** with canonical examples in the description, **never a hard
`enum`** — the manifest grows as advisory families are added. (Per the M1.16 CodeRabbit finding;
re-applied in M1.17–M1.23.)
