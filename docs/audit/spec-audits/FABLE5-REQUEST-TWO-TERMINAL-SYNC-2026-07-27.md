# ЗАПРОС В FABLE-5 — Синхронизация двух терминалов (чтобы не путаться)

Дата: 2026-07-27
От: Central Terminal (Brain) через Factory
Тип: request / open-points
Статус: OPEN → ожидает ответа Fable-5

## Контекст
В работе участвуют ДВА терминала. Возникает путаница ролей и состояния
(кто что делает, чьё состояние актуально, чей голос — исходящий).
Нужен канон синхронизации, устраняющий рассинхрон и путаницу.

## Что просим у Fable-5 (open points)
1. Какой механизм синхронизации состояния между двумя терминалами
   (единый источник истины: ledger / main / общий якорь)?
2. Как разграничить роли, чтобы не путаться: кто Central (Brain),
   кто исполняет, чей вывод считается «голосом Central», а чей — inbound?
3. Протокол очередности: как избежать параллельных/конфликтующих действий
   между терминалами (один артефакт → выдача → следующий)?
4. Как разрешать конфликт состояний (два терминала разошлись):
   правило приоритета / reconcile-процедура?
5. Как фиксировать факт синхронизации (маркер/якорь), чтобы обе стороны
   видели «мы синхронны на точке X»?
6. Минимальный чек-лист «перед началом работы»: что каждый терминал
   обязан прочитать/сверить, чтобы стартовать в синхроне?

## Требуемый ответ от Fable-5
- Пошаговая процедура синхронизации двух терминалов.
- Правило разрешения конфликтов состояния.
- Формат маркера синхронизации.

## Ограничения
- Documentation/governance only; no PROD. PolyForm-NC (sandbox).
