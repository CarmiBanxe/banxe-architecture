# AGENT-REGISTRY — расширение схемы (ADR-BANK-TOPOLOGY-03)

**Статус:** PROPOSED · **Дата:** 2026-08-06 · Экспертиза: Fable-5 + Codex INDEPENDENT.

Реестр — авторитетная таблица фактов; дерево, этажи и карта ответственности —
её проекции. Чтобы проекции доказывали, а не иллюстрировали, реестр обязан
описывать не только «агента», но и каждую разрешённую связку
**агент → инструмент → действие → данные**.

## Существующие колонки (сохраняются)

`agent_id · canonical_name · source_path · class · room · department · floor ·
human_double · SMF · decision_or_tooling · hitl_gate · status`

## Добавляемые колонки

| Колонка | Назначение | Почему обязательна |
|---|---|---|
| `trust_domain` | контур доверия (ordinary / reserved-control) | отделяет ветви MLRO/audit: общий runtime, но нет командного ребра |
| `workload_identity` | уникальная identity нагрузки | запрет общих учёток; отзыв и переаттестация |
| `credentials_owner` + `last_recertification` | владелец и дата пересмотра прав | борьба с identity sprawl |
| `model` + `provider` + `model_version` + `region` | что и где рассуждает | воспроизводимость решения, cross-border |
| `system_prompt_hash` + `policy_version` | версии промпта и политики | доказать, какая версия породила решение |
| `permitted_actions` / `prohibited_actions` | явно разрешённое и запрещённое | least privilege в машиночитаемом виде |
| `tool_bindings` | список «инструмент → действие → данные» | главный недостающий уровень детализации |
| `limits` (сумма / частота / blast radius) | пределы одного агента | ограничение каскада и ущерба |
| `delegation_mandate_id` | ссылка на мандат делегирования | «осознанное делегирование» перестаёт быть словом |
| `fail_safe_mode` + `timeout_behaviour` | поведение при отказе движка | fail-closed по умолчанию, не «пропустить» |
| `kill_switch_owner` | кто может выключить | для reserved-control — НЕ директор |
| `criticality_tier` + `rto_rpo` | критичность и цели восстановления | DORA/operational resilience |
| `data_classification` + `retention` | какие данные и сколько хранит | GDPR minimisation и сроки |
| `monitoring_slo` + `drift_status` | наблюдаемость и дрейф | «200 OK» ≠ корректный контрольный результат |
| `incidents_overrides` | связанные инциденты и отмены | обратная связь для пересмотра мандата |
| `next_review` + `retirement` | когда пересматривать и выводить | против бесшумного накопления агентов |

## Немедленные следствия из текущих данных

- **28 агентов из 132 не имеют `human_double`.** До ратификации ADR-03 каждый
  либо получает названного человека, либо переводится в `tooling` с
  доказательством, что материальных решений не принимает.
- Комнаты `F3-aml` (9 агентов) и `F4-audit-cell` (7) получают
  `trust_domain = reserved-control` и `kill_switch_owner ≠ director`.
- 102 агента класса `decision` — кандидаты на проверку по правилу «агентность
  только там, где нужно суждение»: детерминированные расчёты, проводки, сверки,
  лимиты и сегрегация должны быть обычными сервисами и rules engines.

## Порядок внедрения

1. Колонки добавляются в реестр одним изменением (canonical → требует IL-шард).
2. Заполнение — по комнатам, начиная с `reserved-control` и F2-payments (30 агентов).
3. Генератор проекций расширяется соответствующими срезами после заполнения.
4. Незаполненная обязательная колонка блокирует статус `active` для агента.
