# PREPROD RESTORE CHECKLIST — что включается обратно до прода

**Основание:** директива оператора 2026-08-06 (снять процессные ограничения в проектной
фазе) + консенсус Fable-5 / Codex INDEPENDENT. Переключение — одно: `policy/mode.yaml`.
**Триггер восстановления:** первое production-развёртывание ИЛИ первый реальный клиент
ИЛИ движение реальных денег — что наступит раньше.

## Возвращается переключением режима

| Контроль | sandbox | preprod/prod |
|---|---|---|
| Второе мнение внешней модели | advisory | обязательно на необратимом |
| HITL-акт на merge | выключен | для рискованных изменений |
| Publication gate | secret/PII + smoke + review | полный |
| Сериализация писателя ledger | выключена | для денежного ledger — обязательна |
| Церемония импорта | минимальная | полная с восстановимыми копиями |
| preprod-readiness job | информационный | required |

## Требует отдельной инженерной работы (не переключается)

- **Денежный ledger** — атомарность, идемпотентность, double-entry инварианты,
  сверка, неизменяемый audit trail, проверенное восстановление. Это отдельный
  механизм, а НЕ проектный Redis-счётчик IL-номеров.
- **Управление ключами** — KMS/HSM, ротация, раздельные роли, break-glass,
  запрет долгоживущих секретов в CI.
- **Разделение полномочий** для денежных, клиентских и административных операций.
- **Required CI** по security, миграциям, ledger-инвариантам, контролю доступа,
  backup/restore и supply-chain integrity.
- **Release pipeline** — подписанные/аттестованные артефакты, rollback, approvals.
- **Защита реальных данных** — минимизация, шифрование, retention/deletion,
  журналирование доступа, изоляция сред.
- **Backup/restore и DR** с проверенной сверкой после восстановления.
- **Мониторинг, алерты, incident response**, отзыв credentials, расследование.
- **Threat model**, сканирование зависимостей и контейнеров, защита GitHub Actions.
- **Миграции** — dry-run, обратная совместимость, rollback, запрет необратимых
  изменений без отдельного одобрения.
- **Матрица контролей** — кто отвечает, какое доказательство создаётся, как проверяется.

Каждому отложенному контролю назначается проверяемый приёмочный тест: не «включить
аудит», а «неавторизованное изменение ledger отклоняется и создаёт событие аудита».

## Открытый пункт, который НЕ откладывается

Идентификаторы safeguarding-счетов (CASS) уже опубликованы в публичном репозитории
`banxe-emi-stack`: 17 файлов в `origin/main`, 7 коммитов истории. Это класс
«реальные операционные данные за контролируемой границей» — он остаётся в keep-list
и требует решения владельца контроля (смена идентификаторов либо документированное
принятие риска), а не переноса в прод. Удаление из истории само по себе не отменяет
факта публикации.
