# GLOSSARY.md — Canonical Terminology for the BANXE Factory

> **Status:** governance reference (S6 — Terminology / Glossary half).
> **Scope:** single source of truth for terms used across the BANXE software-factory
> governance corpus (ADR framework, append-only ledger, guardian gates, cluster
> topology, DevSecOps, organizational roles, Open Banking).
>
> **Grounding rule (ADR-102 anti-duplication).** Every definition below is **grounded in
> an existing repo artifact** and cites its source file; this glossary *references* canon,
> it does not restate or fork it. Where a term is used in the corpus but **no definition is
> asserted anywhere in the repo**, the entry is marked **`AWAITS OPERATOR`** rather than
> invented (Operator-supreme canon; invent-no-facts). See the
> [Open-items register](#open-items-register-awaits-operator) at the foot.
>
> This document is **descriptive**, not normative: the cited source file remains
> authoritative for each term. On any divergence, the source wins and this entry is the
> defect.

---

## 1. Purpose & scope

The factory governance corpus spans many domains (decision records, an append-only
instruction ledger, CI guardian gates, on-prem cluster topology, DevSecOps supply-chain
controls, FCA/SMF organizational roles, Open Banking). Terms recur across documents with no
single index. This glossary provides one canonical, repo-grounded lookup so that agents and
operators resolve a term identically.

- **In scope:** terms asserted somewhere in `CarmiBanxe/banxe-architecture`.
- **Out of scope:** project (customer-facing) product terminology not asserted in this repo;
  external-standard prose beyond what the cited source states.
- **Authority:** each entry's **Source** column is authoritative. This file never overrides
  ADR-102 / ADR-103 / ADR-059-A / the merge canon / security canon — it is additive.

## 2. ADR framework

| Term | Definition (repo-grounded) | Source |
|---|---|---|
| **ADR** | Architecture Decision Record — a numbered, immutable record of a governance/architecture decision; created via the `new-adr` skill, stored under `docs/adr/` (and legacy `decisions/`). | `docs/adr/` (corpus); `.claude/` skill `new-adr` |
| **ADR-056** | Ledger-coupling merge gate: a PR that changes tracked paths MUST also add either a new `### IL-NNN` block to `INSTRUCTION-LEDGER.md` or a new `ledger/entries/` shard — couples delivery to the audit trail. Enforced by CI job `guardian-ledger`. | `docs/adr/ADR-056-ledger-coupling-merge-gate.md`; `.github/workflows/guardian.yml` |
| **ADR-057** | Ledger append-only immutability: existing `INSTRUCTION-LEDGER.md` lines may never be removed or modified; corrections are new appended blocks only. Enforced by CI job `ledger-append-only` on both `pull_request` and `push`. | `docs/adr/ADR-057-ledger-append-only-immutability.md`; `.github/workflows/guardian.yml` |
| **ADR-059** | Instruction-ledger append-serialization via per-session shards: replaces the monolithic ledger with per-session shard files; `INSTRUCTION-LEDGER.md` becomes a generated projection, eliminating IL-NNN collisions under parallel sessions. (S3 adds the shard append-only + rebuild gates.) | `docs/adr/ADR-059-il-append-serialization-per-session-shards.md` |
| **ADR-059-A** | Frozen-archive + shard-composition strategy for the cutover: the historical ledger range is frozen as an append-only archive and all new entries are shard files only; the projection is regenerated by `build_ledger.py`. | `instruction-ledger/sprint-53/ADR-059-A-frozen-archive-shard-composition.md`; `ledger/FROZEN-ARCHIVE.md` |
| **ADR-060** | Multi-actor orchestration: namespaced branches `agent/<actor>/<id>/<slug>` (actor ∈ {central, right, factory}), with the `<id>` segment alphanumeric-only and `<slug>` lowercase + `._-`. Enforced by CI job `guardian-branch-naming`; pairs with a pre-push branch-name gate (`scripts/install-hooks.sh`). | `docs/adr/ADR-060-multi-actor-orchestration.md`; `.github/workflows/guardian.yml` |
| **ADR-102** | "No smart refactor without repo-wide duplication verification" — a STOP-barrier hard rule requiring a 5-step **Duplication Audit** (repo-wide search → source-of-truth + every consumer → no delete/merge until hidden deps confirmed → "Duplication Audit" section keep/merge/delete + risks → fail-closed + escalate on doubt) before any structural change. | `docs/adr/ADR-102-no-smart-refactor-without-duplication-verification.md`; `.claude/rules/agents.md` |
| **ADR-103** | Server-only refactoring policy: all refactoring/legacy-handling and secret use run only on a secured server (never an operator local machine); promotion into a repo happens only via the smart-refactor discipline (ADR-102 Duplication Audit on the promotion PR). | `docs/adr/ADR-103-server-only-refactoring-policy.md`; `.claude/rules/agents.md` |
| **ADR-117** | Factory/Project perimeter & full-cycle org model: defines the Factory (Legion, software-delivery only) vs Project (cluster evo1/evo2, regulated compute) boundary and full-cycle factory org roles; ACCEPTED requires all OPERATOR-DECISION placeholders filled (guarded by `guardian-adr117`). | `docs/adr/ADR-117-factory-project-perimeter-and-fullcycle-org.md`; `docs/governance/CANON-RECONCILIATION-ADR117.md` |

## 3. Ledger system

| Term | Definition (repo-grounded) | Source |
|---|---|---|
| **INSTRUCTION-LEDGER.md** | The generated projection of the instruction ledger ("GENERATED ARTIFACT … Do NOT edit by hand"); the source of truth is the shard set under `ledger/entries/**/IL-*.md`. Regenerated via `build_ledger.py`. | `INSTRUCTION-LEDGER.md` (header); `ledger/build_ledger.py` |
| **shard** | A per-session append-only ledger file `ledger/entries/<session_id>/IL-<il_ts>--<sid6>.md` carrying YAML front-matter (`il_ts`, `session_id`, `source`, `status`) plus a markdown body. Only new shards may be added; deletion/rename/edit is forbidden (append-only). | `ledger/README.md`; `ledger/build_ledger.py`; `ledger/entries/` |
| **il_ts** | Shard timestamp field in UTC ISO-8601 with hyphenated time (`YYYY-MM-DDTHH-MM-SSZ` in the filename / `…THH:MM:SSZ` in front-matter). Primary sort key for deterministic ordering; a new shard's `il_ts` must be strictly greater than the current max on `origin/main`. | `ledger/README.md`; `ledger/build_ledger.py` (`sort key (il_ts, session_id, path)`) |
| **session_id** | Stable identifier of the producing session; also the `ledger/entries/<session_id>/` directory name and the tie-break sort key after `il_ts`. | `ledger/build_ledger.py`; `ledger/entries/` |
| **sid6** | First 6 hex chars of `sha1(session_id)`, used as the shard filename suffix `--<sid6>`. | `ledger/build_ledger.py` (`sid6()`) |
| **IL-NNN** | Human-readable sequential ledger entry id (`IL-001`, `IL-002`, …) assigned deterministically at rebuild time from the sorted shard set — never chosen by a session. Format `### IL-NNN - <session_id> @ <il_ts>`. | `ledger/build_ledger.py` (`render()`); `INSTRUCTION-LEDGER.md` |
| **append-only (ledger)** | The discipline that ledger history is immutable: no line of `INSTRUCTION-LEDGER.md` and no committed shard may be deleted or modified; only tail additions are allowed. Realises Invariant I-28; enforced by `ledger-append-only` + `guardian-ledger-shards`. | `INVARIANTS.md` (I-28); `docs/adr/ADR-057-...md`; `.github/workflows/guardian.yml` |
| **build_ledger.py** | The generator that composes `INSTRUCTION-LEDGER.md` from all `ledger/entries/**/IL-*.md`, sorting by `(il_ts, session_id, path)` and assigning IL-NNN; `--check` verifies the committed file equals a fresh rebuild (CI). | `ledger/build_ledger.py` |
| **FROZEN-ARCHIVE.md** | The frozen historical ledger prefix prepended by `build_ledger.py`; IL-NNN numbering for new shards continues from its max. | `ledger/FROZEN-ARCHIVE.md`; `ledger/build_ledger.py` (`render()`) |
| **I-28** | Invariant: Instruction Ledger Discipline / Execution Accountability — every instruction is recorded in the ledger and history is append-only; status `DONE` requires proof. Violation = blocking defect. | `INVARIANTS.md` (I-28); `CLAUDE.md` §0 |

## 4. Guardian gates (CI)

All gates live in `.github/workflows/guardian.yml` (with `guardian-adr117` delegating to a script).

| Term | Definition (repo-grounded) | Source |
|---|---|---|
| **guardian-ledger** | PR gate (ADR-056): fails a PR that touches tracked paths without adding a new `### IL-NNN` block or a new shard, and rejects ledger deletions. | `.github/workflows/guardian.yml` (`guardian-ledger`) |
| **ledger-append-only** | Gate (ADR-057) on `pull_request` and `push`: fails if any existing `INSTRUCTION-LEDGER.md` line is removed/modified (defence-in-depth alongside `guardian-ledger`). | `.github/workflows/guardian.yml` (`ledger-append-only`) |
| **guardian-ledger-shards** | PR gate (ADR-059 S3): fails if any `ledger/entries/` shard is deleted/renamed/modified (append-only), and verifies `build_ledger.py --check` (generated == rebuild). | `.github/workflows/guardian.yml` (`guardian-ledger-shards`) |
| **guardian-branch-naming** | PR gate (ADR-060): enforces `^agent/(central\|right\|factory)/[A-Za-z0-9]+/[a-z0-9._-]+$` (with `dependabot/ renovate/ revert/` allow-listed). | `.github/workflows/guardian.yml` (`guardian-branch-naming`) |
| **guardian-adr117** | Gate: blocks ADR-117 `ACCEPTED` while any `OPERATOR-DECISION` placeholder remains unfilled; implemented by `scripts/adr117-gate-check.sh`. | `.github/workflows/guardian.yml`; `scripts/adr117-gate-check.sh` |
| **guardian-schemas / guardian-factory / guardian-project** | Companion gates: enforce S2 governance JSON-Schemas; presence of the factory agent registry (`agents/souls`, `agents/passports`, `.claude/agents`); and project invariants (`README.md`). | `.github/workflows/guardian.yml` |
| **Canon Judge** | An LLM-based evaluation component (`canon_judge/`) that scores agent output against deterministic canon rules in **audit mode** (WARN/PASS, log-only, non-blocking) per the software-factory canon. | `docs/canon/software-factory-canon-v1.md` |
