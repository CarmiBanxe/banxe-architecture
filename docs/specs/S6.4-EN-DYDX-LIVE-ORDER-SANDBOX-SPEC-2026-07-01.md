## A. Scope — enable, not build (ADR-102 reuse)

S6.4-EN enables the **already-built** dYdX `ExchangePort` adapter to place/cancel/status **unsigned** orders against the dYdX **sandbox/testnet**, gated behind the existing kill-switch, **mock-default**. Enable-not-build: no new adapter, no new port.

## B. Flag / config (kill-switch fail-closed)

| Flag | mock (CI/default) | sandbox-live (this sprint) | Notes |
|---|---|---|---|
| `BANXE_DSE_LIVE_ALLOWED` | unset/false | `true` | master kill-switch |
| `dydx_submit_enabled` (`BANXE_DYDX_SUBMIT_ENABLED`) | **False** (default) | `true` | **per-venue kill-switch**; submission stays off unless BOTH this + a valid `dydx_node_url` |
| `dydx_node_url` | — | dYdX **testnet** node (Phase-2a) | mainnet node = Phase-2b separate GO |
| exchange provider/mode | mock | `dydx` + sandbox-live | any other combo / error → **fail-closed to mock/no-submit** |

- **Fail-closed:** any flag unset/false, missing node URL, or adapter error → **no submission; fall back to mock**. Never a silent live submit, never a hard 5xx.
- All thresholds/URLs/timeouts = config-as-data (§10); **no keys/values in code or this spec** (vault only, per ODR-1).

## C. Mandatory controls (RED-zone — all required before any live submit)

1. **Ruflo MANDATORY** on the order-placement surface (payment/compliance-classed — BUG-005); order routes through the regulatory check.
2. **HITL on live order** (BUG-007): live order placement requires human-in-the-loop confirmation per the AUTO/REVIEW/BLOCK thresholds; no autonomous live execution.
3. **Kill-switch** `dydx_submit_enabled` defaults **False**; arming is an explicit operator act (Phase-2b for mainnet).
4. **Sandbox/testnet FIRST** — no mainnet, no real funds, in Phase-2a. Mainnet = Phase-2b, separate GO.
5. **Idempotency** on `clientOrderId` (no duplicate submits on retry).
6. **Server-side build only** (ADR-103, evo1).

## D. Self-custodial moat (unchanged — ADR-083)

- The backend **constructs an unsigned order intent**; the **client wallet signs every order**; the backend **never signs, never holds keys, never executes as principal**.
- **Live execution = Paybis principal** (ODR-3 distributor posture); BANXE **routes** the unsigned intent. BANXE does not act as the executing principal.
- No custody, no autonomous market-making (out of scope).

## E. Acceptance criteria + conformance-test plan

**Acceptance:**
- [ ] Flag gate: `dydx` + sandbox-live + `LIVE_ALLOWED=true` + `dydx_submit_enabled=true` + valid testnet `dydx_node_url` → routes to the built adapter for **testnet** submit. **Any other combo = mock/no-submit.**
- [ ] **Mock remains CI/default**; existing exchange suite stays green, no live network in CI.
- [ ] **Fail-closed:** missing node URL / kill-switch off / adapter error → no submit, mock fallback, logged.
- [ ] Unsigned-intent path: backend produces an unsigned order intent; **assert no signature / no key** in backend.
- [ ] Ruflo intercepts the order surface; HITL gate present for live order.
- [ ] Idempotency on `clientOrderId`.

**Conformance tests (extend the exchange suite; NO live network/keys in CI):**
1. **Selection matrix** — dydx-submit only under the full combo; mock/no-submit otherwise.
2. **Fail-closed** — kill-switch off / no node URL / error → no submit, mock fallback asserted.
3. **Unsigned intent** — backend signs nothing; client-sign path asserted.
4. **Ruflo + HITL** — order surface routes through Ruflo; HITL gate asserted.
5. **Idempotency** — duplicate `clientOrderId` → single submit.
6. **I-01** — order qty/price decimal strings; no float.
