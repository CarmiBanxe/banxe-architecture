## Root cause (2nd battle-run defect, confirmed 2026-07-06 02:34:43)

v2.1 sync-before-scan correctly detected **30 status=NEW findings** on
`origin/main:governance/NOVELTY-COLLECTION-REGISTER.md` and attempted to spawn
an isolated worktree via `scripts/bx-session.sh` (ADR-120). The worktree branch
name it requested was:

    agent/factory/watcher-handoff/current

`scripts/bx-session.sh` line 17 enforces the ADR-060 pattern (mirror of
`guardian.yml`):

    ^agent/(central|right|factory|specproj)/[A-Za-z0-9]+/[a-z0-9._-]+$

The `<id>` segment is `[A-Za-z0-9]+` — **no hyphens allowed**. The segment
`watcher-handoff` contains a hyphen, so `bx-session.sh` refused the branch
(`branch '…' violates ADR-060 …`). The watcher then hit the guard at
`novelty-watcher.sh` line 428:

    [ -d "${wt_path}" ] || die "bx-session.sh did not return a valid worktree path: ${wt_path}"

so no worktree was created, and per line 481 the watcher `deferred writes to
next run` — hand-off events never landed.

## Fix (v2.2)

`scripts/novelty-watcher.sh` — `WATCHER_BRANCH` default renamed:

    -WATCHER_BRANCH="${BX_WATCHER_BRANCH:-agent/factory/watcher-handoff/current}"
    +WATCHER_BRANCH="${BX_WATCHER_BRANCH:-agent/factory/watcherhandoff/current}"

`<id>` = `watcherhandoff` — pure `[A-Za-z0-9]+`, ADR-060 compliant.
`<slug>` = `current` — already `[a-z0-9._-]+` compliant.

**Preserved (unchanged):** v2.1 sync-before-scan, v1.1 strict-NEW filter, v2
fail-open LiteLLM :4000 scoring, single-writer / idempotent hand-off writes.
