## Finding 1 — CRITICAL: Zero secret rotation policy in place

**Gap ID:** G-SEC-01, G-IAM-05
**Severity:** CRITICAL

ADR-017 §5 committed a 90-day rotation cadence for the four `KC_CLIENT_SECRET_*` values
as part of the Keycloak IAM cutover. As of 2026-05-06, G-IAM-05 status remains NOT_STARTED
in `GAP-REGISTER.md:156`. No cron, calendar entry, n8n workflow, runbook chapter, or alerting
rule exists that would prompt or execute any credential rotation for any secret in the stack.

The five n8n workflows in `banxe-emi-stack/n8n/workflows/` and `config/n8n/` are:
- `safeguarding-shortfall-alert.json` — FCA CASS 15 shortfall notification
- `daily-recon-report.json` — reconciliation summary
- `complaint-sla-monitor.json` — Consumer Duty SLA monitor
- `mcp-health-monitor.json` — MCP server health
- `shortfall-alert-workflow.json` — duplicate/variant of above

None relate to credential lifecycle management.

**Evidence:** `GAP-REGISTER.md:156`, `MASTER-PLAN-2026-05-05.md:65-72`, n8n workflow directory listing.

## Finding 2 — HIGH: IL-SEC-01 is incident-scoped, not a general policy

**Gap ID:** G-SEC-01 (contributing factor)
**Severity:** HIGH

IL-SEC-01 (`INSTRUCTION-LEDGER.md:3283`) was created on 2026-05-05 after `docker inspect
banxe-frankfurter` exposed a plaintext `DATABASE_URL` containing a Postgres password in a
terminal session. The ledger entry defines a 5-step action plan specific to the Frankfurter
Postgres credential:

1. Generate new password via `openssl rand -base64 32`
2. Provision new DB if/when Frankfurter is redeployed
3. Document in `.banxe/secrets-vault/`
4. Update env var via secret-injection (not CLI)
5. Scrub shell history

As of audit date, IL-SEC-01 status is **OPEN** — no steps completed. This incident entry does
not address the broader secret surface (KC secrets, external API keys, GitHub PATs, JWT signing
key, Telegram bot token).

**Evidence:** `INSTRUCTION-LEDGER.md:3283-3315`.

## Finding 3 — HIGH: Rotation events absent from ClickHouse audit trail (I-24 gap)

**Gap ID:** G-SEC-01 (audit trail dimension)
**Severity:** HIGH

Invariant I-24 requires append-only audit records in ClickHouse for all operational actions.
Secret rotation is an operational action with direct security impact. No `ROTATION_DUE`,
`ROTATION_COMPLETED`, or equivalent event type exists in the `safeguarding_audit` ClickHouse
schema. ADR-027 `BufferedAuditPort` is Proposed (not yet implemented); no rotation event types
are defined in its schema.

Consequence: an external auditor inspecting ClickHouse cannot determine whether any credential
was ever rotated, when, or by whom. FCA SYSC 15A evidence reconstruction for a past period is
impossible.

**Evidence:** ADR-027 (Proposed), `src/safeguarding/audit_trail.py`, absence of ROTATION_*
event type in any schema file.

## Finding 5 — MEDIUM: IL-SEC-01 Frankfurter exposure — rotation not executed

**Gap ID:** IL-SEC-01 (open, P1)
**Severity:** MEDIUM

The Frankfurter Postgres password was confirmed exposed on 2026-05-05 (printed to terminal
during PA-5a). IL-SEC-01 status is OPEN as of audit date. The target Postgres DB does not
currently exist on evo1 (no listener on :5432 confirmed during PA-5a), which reduces immediate
blast radius, but the password value is compromised and must be rotated before any Frankfurter
redeployment.

Additionally, `pa-05-frankfurter-decommission.md` (PR #70) documents that the Frankfurter
service is decommissioned, but the rollback plan §"Rollback plan" requires a new Postgres DB
with the rotated password from IL-SEC-01. If rollback is ever executed, this gap becomes CRITICAL.

**Evidence:** `INSTRUCTION-LEDGER.md:3283-3315`, `docs/runbooks/pa-05-frankfurter-decommission.md`.

## Finding 6 — MEDIUM: GitHub Actions secret cadence undocumented

**Gap ID:** G-SEC-01 (scope extension)
**Severity:** MEDIUM

GitHub Actions secrets (used in CI/CD: `quality-gate.yml`, `lint-python.yml`, `lint-frontend.yml`,
`alembic-check.yml`, guardian-shim workflows) include at minimum:
- `GITHUB_TOKEN` (auto-provisioned per-workflow, no rotation needed)
- PATs for registry push and cross-repo operations (custom, rotation required)

No last-rotated date, expiry policy, or rotation reminder exists for custom PATs. GitHub's
default PAT expiry is configurable; classic PATs can be set to "no expiry" which is the
highest-risk configuration. This cannot be audited from the repository alone — requires
operator inspection of `Settings > Developer Settings > Personal Access Tokens`.

**Evidence:** `.github/workflows/` directory, absence of any PAT rotation record in IL or
GAP-REGISTER.

## Finding 7 — LOW: ADR-017 §5 cadence defined but enforcement mechanism absent

**Gap ID:** G-IAM-05 (root cause)
**Severity:** LOW

ADR-017 §5 (`decisions/ADR-017-keycloak-iam-cutover.md`) specified the 90-day rotation cadence
as a requirement. G-IAM-05 was opened in GAP-REGISTER.md to track enforcement. The gap has been
open since at least 2026-05-03 (G-IAM-06 done date) with no forward motion. The
`infra/keycloak-banxe-emi/scripts/provision-clients.sh` script is described as "re-runnable for
rotation" in `GAP-REGISTER.md:51`, but it is a provisioning script, not a rotation workflow —
it does not implement the dual-key grace window, audit logging, or approval gate required by
ADR-032 option (b).

**Evidence:** `GAP-REGISTER.md:156`, `infra/keycloak-banxe-emi/scripts/` directory,
`ROADMAP.md:1940`.

## Recommendations

- Adopt ADR-032 Option (b): n8n scheduled workflows + IL-SEC-01 runbook fallback.
- Close IL-SEC-01 by executing Frankfurter password rotation before any redeployment.
- Extend ADR-027 `BufferedAuditPort` schema with `ROTATION_DUE` / `ROTATION_COMPLETED` event types.
- Add `GITHUB_PAT` rotation to ADR-032 cadence matrix; operator to audit GitHub PAT expiry settings.
- Open G-SEC-02 stub ADR (Vault/Infisical adoption) as long-term placeholder per ADR-032 §Implementation Plan step 5.
