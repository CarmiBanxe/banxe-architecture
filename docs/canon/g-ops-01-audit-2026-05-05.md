**Audit date:** 2026-05-05
**Auditor:** Architecture WG (Claude Code CCF §15)

**Closes via:** ADR-029 (Proposed, same PR)
**Cluster:** evo1 (192.168.0.72)
**Linked:** SERVICE-MAP.md §Серверы кластера, V-07 (HANDOFF-2026-05-04)

## Audit Scope

Read-only audit of evo1 PostgreSQL infrastructure:
- `docker ps -a` — all container states
- `docker volume ls` — all named volumes
- Cron tabs: `root`, `banxe`, `mmber`, `ctio`
- `docker inspect` for running containers

---

## Executive Summary

**Zero backup infrastructure exists on evo1.** No pg_dump cron, no WAL archiving, no
backup scripts were found in any cron tab. Seven PostgreSQL containers are present; only
one is RUNNING. An OOM kill (exit code 137) was observed on the Keycloak PostgreSQL
container, confirming active memory pressure on evo1. A disk failure or memory cascade
would destroy all regulated financial data simultaneously.

**Critical scope correction:** `midaz-ledger` uses MongoDB (`mongo:8`, port 5703,
replica set `rs0`), NOT PostgreSQL. V-07's reference to "WAL-G for Midaz ledger primary"
is inapplicable to PostgreSQL. Midaz MongoDB backup is a separate gap.

## Finding 1 — Zero PostgreSQL Backup Infrastructure (CRITICAL)

**Evidence:** Audit of all cron tabs on evo1:

```
# crontab -l -u root   → No pg_dump, pg_basebackup, or backup script entries
# crontab -l -u banxe  → No backup entries
# crontab -l -u mmber  → No backup entries
# crontab -l -u ctio   → No backup entries
```

No files matching `*backup*`, `*pg_dump*`, `*wal*` found under `/opt/banxe/scripts/`,
`/root/`, `/home/banxe/`, or `/etc/cron.d/`.

**Regulatory impact:**
- FCA CASS 15 §15.10: daily reconciliation evidence in `banxe_compliance` DB is
  unprotected; a disk failure constitutes an immediate reportable compliance failure.
- MLR 2017 Reg.28: AML/KYC evidence must be recoverable for ≥5 years; zero-day
  retention fails this requirement.
- DORA Art.14(2): ICT operational records must be complete and tamper-proof; no
  backup means no ICT continuity plan can be defined.

**Severity:** CRITICAL  
**Remediation:** ADR-029 Option (b) + (c) — pg_dump daily + MinIO evo2 + WAL-G

**Severity:** HIGH

## Finding 5 — Keycloak OOM Kill Pattern (G-OPS-01 Amplifier)

**Evidence:** `docker inspect keycloak-banxe-emi_db`:

```json
"State": {
  "Status": "exited",
  "ExitCode": 137,
  "FinishedAt": "2026-05-04T..."
}
```

Exit code 137 = SIGKILL from OOM killer. The Keycloak PostgreSQL instance was
OOM-killed; restart without backup means any realm data written since last backup
would be unrecoverable. Currently, "last backup" = never.

Keycloak realm contains: all staff accounts, RBAC role assignments, HITL approver
roles (MLRO, CEO, CRO), OAuth2 clients for all services. Loss of realm = complete
IAM failure requiring manual reconstruction from Terraform/IaC (if it exists).

**Severity:** HIGH  
**Remediation:** pg_dump of Keycloak DB added to daily cron as P0 priority; heap limit
review for KC JVM (`-Xmx` flag) to reduce OOM recurrence

---

## Finding 6 — Restore Drill Absent (G-OPS-02)

**Evidence:** No restore drill script, cron entry, or log file found on evo1 or evo2.
V-07 explicitly: "Backup rotation not validated post-migration."

DORA Art.14(2) requires ICT continuity testing. FCA SYSC 15A requires backup integrity
validation. A backup that has never been tested provides no assurance of recoverability.

**Severity:** HIGH  
**Remediation:** ADR-029 Implementation Plan §4 — weekly automated restore drill on evo2
staging DB; success/failure logged to `/var/log/restore-drill.log`; alert on failure

---

## Finding 7 — banxe_compliance Exited(128) — Compliance DB Dark

**Evidence:** `banxe-postgres` (postgres:16, port 5432) is in Exited(128) state.
Exit code 128 = abnormal exit (non-signal). The `banxe_compliance` database — which
contains AML screening results, KYC workflow state, safeguarding audit events, and
reconciliation records — is not running.

This means:
- No new AML/KYC data is being written during the Exited period
- The FastAPI compliance API (port 8093) cannot reach its primary DB
- Any data written to the running ClickHouse audit trail cannot be cross-referenced
  with PostgreSQL KYC state

**Severity:** CRITICAL (operational gap independent of backup)  
**Remediation:** Root cause investigation of Exited(128) required before backup can
be validated; tracked separately from ADR-029 (operational restart, not backup strategy)

## Remediation Path

ADR-029 (Proposed, same PR) addresses all findings. Implementation requires:
1. MinIO on evo2 — operator deployment action
2. `banxe-pg-backup.sh` cron — engineering implementation
3. WAL-G for `banxe_compliance` — engineering implementation + KC heap limit review
4. Weekly restore drill — engineering implementation

No compliance control is fully closed until implementation PR merges and first
successful restore drill is logged. Gap status: **G-OPS-01 OPEN**, **G-OPS-02 OPEN**.
