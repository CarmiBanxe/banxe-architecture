## Finding 1 — CRITICAL: eventsListeners absent — KC events reach no external channel

**Gap ID:** G-OBS-01
**Severity:** CRITICAL

`infra/keycloak-banxe-emi/realms/banxe-emi-realm.json` contains:
```json
"eventsEnabled": true,
"adminEventsEnabled": true,
"adminEventsDetailsEnabled": true
```

The `eventsListeners` key is **absent** from the realm export. In Keycloak, the absence of
`eventsListeners` means the default `jboss-logging` listener is the sole active sink —
all auth events are written to the KC application log and to the KC internal DB, and nowhere
else. The internal DB default `eventsExpiration` in KC is 0 (events never expire, but are
also never externally accessible without KC Admin API polling).

Consequence: `LOGIN_ERROR`, `CLIENT_LOGIN_ERROR`, `TOKEN_EXCHANGE_ERROR`, `DELETE_USER`,
`UPDATE_PASSWORD` (admin), and all 18 other KC event types are captured internally but
silently discarded from an ops-visibility perspective. No alert, no audit trail entry, no
notification reaches any human or system outside KC.

**Evidence:** `infra/keycloak-banxe-emi/realms/banxe-emi-realm.json` lines 21-23; absence of
`eventsListeners` key confirmed via `jq '.eventsListeners // "NOT_FOUND"'`.

## Finding 2 — CRITICAL: No PagerDuty, Alertmanager, or Slack webhook in stack

**Gap ID:** G-OBS-01 (V-10 reframe)
**Severity:** CRITICAL

V-10 (HANDOFF-2026-05-04) described the gap as "Keycloak realm alerts not wired to PagerDuty".
Audit confirms PagerDuty is not deployed anywhere in the stack. `grep -rn "PagerDuty|pagerduty"
banxe-emi-stack banxe-architecture` returns only:
- `services/recon/cron_daily_recon.py:21` — comment referencing PagerDuty as a future target
- `agents/compliance/soul/mcp_server_agent.soul.md` — soul file reference
- `GAP-REGISTER.md:261` — gap description itself
- `HANDOFF-2026-05-04-guardian-canon.md:62` — V-10 source document

No Alertmanager (`alertmanager.yml`, `alert.rules.yml`) and no Slack webhook configuration
was found in either repository. This means the gap is wider than V-10 described: it is not
simply that PagerDuty is missing, but that no alert routing destination of any kind is
configured for KC events.

**Evidence:** grep output across both repos; absence of `alertmanager*`, `slack_webhook*`,
`pagerduty*` files in `infra/`, `config/`, `n8n/workflows/`.

## Finding 3 — HIGH: n8n Telegram alert pattern exists but not wired to KC events

**Gap ID:** G-OBS-01 (opportunity assessment)
**Severity:** HIGH (gap, not risk — existing pattern is an unconnected asset)

Five n8n workflows exist in `banxe-emi-stack/n8n/workflows/` and `config/n8n/`:

| Workflow file | Alert channel | Trigger |
|-------------|-------------|--------|
| `safeguarding-shortfall-alert.json` | Telegram (MLRO + CEO) | FCA shortfall threshold |
| `complaint-sla-monitor.json` | Telegram | Complaint SLA breach |
| `mcp-health-monitor.json` | Telegram | MCP server health |
| `daily-recon-report.json` | (report, not alert) | Daily cron |
| `shortfall-alert-workflow.json` | Telegram | Variant of shortfall |

The Telegram delivery pattern (`POST https://api.telegram.org/bot${TELEGRAM_BOT_TOKEN}/sendMessage`)
is operational and tested in production for safeguarding alerts. The `TELEGRAM_BOT_TOKEN`,
`TELEGRAM_MLRO_CHAT_ID`, and `TELEGRAM_CEO_CHAT_ID` variables are already set in the n8n
environment. **Zero of these workflows receive or process Keycloak auth events.** The reuse
path (add n8n webhook receiver + Switch node routing) is the lowest-effort implementation.

**Evidence:** `n8n/workflows/*.json` directory listing; grep for `kc-event|kc_event|keycloak.event`
returns 0 matches in all workflow files.

## Finding 4 — HIGH: No KC SPI Event Listener plugin deployed

**Gap ID:** G-OBS-01 (implementation gap)
**Severity:** HIGH

No custom `EventListenerProvider` JAR was found in `infra/keycloak-banxe-emi/` or any
`providers/` directory. The grep for `EventListenerProvider|SPI` in `infra/` and `services/`
returns no KC-specific results (only unrelated fingerprint engine matches). This means:

1. No HTTP webhook dispatcher JAR is in the KC container image.
2. The `http-event` listener (available natively in KC >= 18.x via built-in
   `org.keycloak.events.EventListenerProvider`) may or may not be available depending on
   the exact KC image version deployed.
3. If `http-event` is not native to the deployed version, a minimal Java JAR must be
   compiled and mounted into the KC container.

**Evidence:** `infra/keycloak-banxe-emi/` directory listing; grep for SPI/EventListenerProvider.

## Finding 5 — HIGH: KC event retention is 0 days (default) — FCA SYSC 15A gap

**Gap ID:** G-OBS-01 (retention dimension)
**Severity:** HIGH

The realm export does not set `eventsExpiration`. Keycloak's default `eventsExpiration` is
0, which means events are never deleted from the KC DB — but also means the KC DB grows
unboundedly and is the sole persistent store. FCA SYSC 15A requires operational records to
be retained and accessible. KC internal DB is not the intended evidence store (ClickHouse
is, per ADR-027 and I-24). Until `eventsExpiration` is set AND events are forwarded to an
external system, there is no durable, auditable event history.

**Evidence:** Absence of `eventsExpiration` in `banxe-emi-realm.json`; KC docs default.

## Finding 6 — MEDIUM: Alert delivery events not logged to ClickHouse (I-24 gap)

**Gap ID:** G-OBS-02 (audit trail dimension)
**Severity:** MEDIUM

Even if alert routing were configured today, no mechanism exists to log `ALERT_DELIVERED`
events to ClickHouse. ADR-027 `BufferedAuditPort` is Proposed but not yet implemented.
The current `AuditTrail.log()` schema in `src/safeguarding/audit_trail.py` does not include
an `ALERT_DELIVERED` event type. An auditor cannot determine whether any KC security event
was ever received, processed, or delivered to an on-call owner.

**Evidence:** ADR-027 (Proposed, not Accepted); `src/safeguarding/audit_trail.py` event types.

## Recommendations

- Adopt ADR-033 Option (a): n8n webhook receiver + Telegram routing.
- Set `eventsListeners: ["jboss-logging", "http-event"]` in realm export.
- Set `eventsExpiration: 7776000` (90 days) in realm export.
- Verify `http-event` listener availability in KC container image version.
- Add `ALERT_DELIVERED` event type to ADR-027 BufferedAuditPort schema.
- Implement G-OBS-02 smoke test: `test_kc_alert_smoke.py` with `@pytest.mark.smoke`.
- Open ADR-034 (PagerDuty escalation) as Status: Deferred for P1 24/7 on-call rota.
