## 2. Findings

### Finding 1 — `KYCWorkflowPort` has no `trigger_reverification()` method (CRITICAL)

**File:** `services/kyc/kyc_port.py`
**Severity:** CRITICAL
**Regulatory exposure:** FCA MLR 2017 Reg.27/28

`KYCWorkflowPort` (Protocol) defines 6 methods:

```
create_workflow() / get_workflow() / submit_documents()
approve_edd() / reject_workflow() / health()
```

There is no `trigger_reverification(customer_id, reason)` method. Any code path
that detects a post-onboarding material change (role grant, UBO mutation, sanctions
match, jurisdiction change) has no KYC interface to call. The gap is at the Port
level — all adapters (mock, Ballerine) would need to implement the method once added.

---

### Finding 2 — `org_roles.py` is a gate-checker, not a role-mutation service (HIGH)

**File:** `services/hitl/org_roles.py`
**Severity:** HIGH

`OrgRoleChecker.check()` validates whether a set of approver roles satisfies a
`HITLGate`. `GATE_REGISTRY` maps `HITLTrigger → HITLGate`. There is no
`assign_role()` method, no `role_assignments` table interaction, and no event
emission. The file correctly defines `OrgRole` enum (CEO, CFO, CRO, MLRO,
COMPLIANCE_OFFICER, etc.) but there is no service layer that performs role mutation
and emits a domain event on completion.

**Consequence:** Even if a `trigger_reverification()` Port method existed, there
is no code path that would call it on role grant — because role grant itself has
no implementation in the current codebase.

---

### Finding 3 — Event Bus exists but lacks role-mutation event types (HIGH)

**File:** `services/events/event_bus.py`
**Severity:** HIGH

`BanxeEventType` enum has 22 event types covering payment, KYC status, AML, and
safeguarding events. Notably present:

```python
KYC_APPROVED = "kyc.approved"
KYC_REJECTED = "kyc.rejected"
RISK_LEVEL_CHANGED = "aml.risk_level_changed"
```

Notably absent:

```python
# MISSING — needed for ADR-028
ROLE_CHANGED               # role_grant_high_risk trigger
BENEFICIAL_OWNER_CHANGED   # UBO mutation trigger
JURISDICTION_CHANGED       # country_of_residence trigger
KYC_REVERIFICATION_TRIGGERED  # downstream confirmation
```

`InMemoryEventBus` and `RabbitMQEventBus` implementations are complete and
production-ready. The gap is the event types, not the bus infrastructure.

**STOP condition assessment:** Bus EXISTS with infrastructure but NO role-change
event types or emitters. ADR-028 proceeds as "extend existing bus" rather than
"create new bus."

---

### Finding 4 — `lifecycle_observer.py` has no role-mutation subscription (MEDIUM)

**File:** `services/customer_lifecycle/lifecycle_observer.py`
**Severity:** MEDIUM

`LifecycleObserverPort` Protocol has 3 methods:

```python
on_transition(event: TransitionObservedEvent) -> None
on_guard_failure(event: GuardFailureEvent) -> None
on_edd_breach(event: EddBreachObservedEvent) -> None
```

There is no `on_role_changed()` handler and no subscription to any `ROLE_CHANGED`
event type from the event bus. The observer is purely reactive to FSM state transitions
— it does not observe external state mutations that should trigger FSM transitions.

---

### Finding 5 — FSM has no `KYC_RE_VERIFICATION_REQUIRED` state (MEDIUM)

**File:** `services/customer_lifecycle/lifecycle_engine.py` (lines 28–56)
**Severity:** MEDIUM

Current `CustomerState` values and `_FSM` edge table:

```
PROSPECT → (SUBMIT_APPLICATION) → ONBOARDING
ONBOARDING → (COMPLETE_KYC) → KYC_PENDING
KYC_PENDING → (ACTIVATE) → ACTIVE
ACTIVE → (FLAG_DORMANT | SUSPEND | CLOSE) → ...
```

There is no `KYC_RE_VERIFICATION_REQUIRED` state and no `REQUIRE_REVERIFICATION`
event. A customer who should be re-verified post-onboarding has no valid FSM path
to re-enter the KYC process without manual intervention or state corruption.

The ADR-LCY-01 canonical FSM (accepted) also does not include this state — adding it
requires an addendum to ADR-LCY-01.

---

### Finding 6 — `customer_lifecycle.py` router uses module-level singleton (LOW)

**File:** `api/routers/customer_lifecycle.py` lines 20–21
**Severity:** LOW

```python
_engine = LifecycleEngine()
_agent = LifecycleAgent(_engine)
```

Module-level singleton without dependency injection. When `OrgRoleService` is added
and must share an `EventBusPort` with the lifecycle observer, the singleton pattern
will require refactoring to FastAPI `Depends()`. This is not a blocker for ADR-028
but must be addressed before wiring the event subscriber at startup.

---

### Finding 7 — `lifecycle_observer.py` not connected to `lifecycle_engine.py` (LOW)

**File:** `services/customer_lifecycle/` (cross-file)
**Severity:** LOW

`LifecycleEngine` does not accept a `LifecycleObserverPort` in its constructor.
`LifecycleEngine.transition()` writes to `self._transition_log` (a list) but does
not call any observer. The observer infrastructure exists but is not wired to the
engine — meaning even the existing `on_transition` events are only emitted if
a caller manually calls `observer.on_transition()` after getting a `TransitionResult`.

## 3. Trigger Inventory

### Currently implemented (audit-confirmed in code)

| Trigger type | Location | Notes |
|-------------|---------|-------|
| Initial KYC guard on ACTIVATE | `lifecycle_engine.py` line 136 | Guard condition only; no re-trigger |
| EDD breach observation | `lifecycle_observer.py` `on_edd_breach()` | Observer method exists; not called by engine |
| SANCTIONS_HIT auto-block (HITL-003) | `org_roles.py` GATE_REGISTRY | Gate definition only; no call path |

### Currently absent (G-KYC-01 gap)

| Trigger type | Regulatory basis | Implementation status |
|-------------|-----------------|----------------------|
| `role_grant_high_risk` (MLRO, AML_OFFICER, SIGNATORY) | MLR 2017 Reg.27/28 | MISSING — no `OrgRoleService`, no emitter |
| `beneficial_owner_change` | MLR 2017 Reg.28 | MISSING — no UBO mutation service |
| `sanctions_hit_active` (post-onboarding match) | SAMLA 2018; MLR 2017 Reg.27 | MISSING — no re-trigger path for active customers |
| `jurisdiction_change` | MLR 2017 Reg.27 | MISSING — no address mutation listener |
| `24_month_review` | MLR 2017 Reg.27 (periodic review) | MISSING — no scheduled timer |

## 5. Regulatory Exposure Assessment

| Regulation | Requirement | Current gap | Severity |
|-----------|------------|-------------|----------|
| MLR 2017 Reg.27 | Ongoing monitoring of business relationships | No monitoring of role/UBO/jurisdiction changes | HIGH |
| MLR 2017 Reg.28 | Re-apply CDD on customer circumstance change | No mechanism to trigger re-CDD post-onboarding | HIGH |
| FCA SS21/3 §3.2 | Trigger events must produce immutable audit records | No trigger events emitted → nothing to record | HIGH |
| SAMLA 2018 | Active customer sanctions match → freeze + re-KYC | `SANCTIONS_HIT` gate defined but no re-KYC path for active customers | CRITICAL |

## 6. Remediation Path

The remediation is specified in **ADR-028** (decisions/ADR-028-kyc-reverification-triggers.md).

Recommended approach: **Option (a) — Extend existing Domain Event Bus** with
**Option (c) Outbox** for CRITICAL-severity triggers only.

| Phase | Action | Priority |
|-------|--------|----------|
| Implementation | Add `ROLE_CHANGED` + related types to `BanxeEventType` | P0 |
| Implementation | Create `OrgRoleService` with outbox for CRITICAL role grants | P0 |
| Implementation | Add `trigger_reverification()` to `KYCWorkflowPort` | P0 |
| Implementation | Wire `on_role_changed()` subscriber in `lifecycle_observer.py` | P0 |
| Implementation | Add `KYC_RE_VERIFICATION_REQUIRED` state to FSM + ADR-LCY-01 addendum | P0 |
| Test (G-KYC-02) | 5 trigger-type CI fixtures using InMemory stubs | P0 |
| Migration | `role_event_outbox` table (Alembic, per 60-migrations.md spec) | P0 |
