## Executive Summary

**Zero smoke-gate or end-to-end test job exists in any GitHub Actions workflow.**
All 7 workflow files operate at unit/lint level: `pytest` runs against InMemory stubs
with no live service containers. Branch protection on `main` requires only Guardian
shim checks (`guardian-factory`, `guardian-project`); `quality-gate` is **not** a
required check. A PR can merge into `main` with failing unit tests if Guardian checks
pass. No `@pytest.mark.smoke` markers or `tests/test_smoke/` module exist.
Docker-compose stacks exist under `docker/` but are not referenced in any workflow.

---

## Finding 1 — Zero Smoke Gate in CI (CRITICAL)

**Evidence:** All workflow files audited (7 total):

| Workflow file | Trigger | Jobs | Docker services | Smoke surface |
|--------------|---------|------|-----------------|--------------|
| `quality-gate.yml` | push/PR to main | ruff, biome, test, semgrep, vitest, secrets-scan | None | None |
| `lint-python.yml` | push (*.py, pyproject.toml) | ruff | None | None |
| `lint-frontend.yml` | push (frontend/**) | biome | None | None |
| `alembic-check.yml` | push (models/migrations) | alembic-check | SQLite only | None |
| `claude-daily-report.yml` | schedule (07:00 UTC M-F) | claude-daily-report | None | None |
| `claude-issue-triage.yml` | issue opened/labeled | claude-triage | None | None |
| `claude-release-readiness.yml` | workflow_dispatch | claude-release-readiness | None | None |

No `docker compose up`, no `services:` containers, no smoke test job in any workflow.

**Attack vector:** A regression in `api/main.py` lifespan, `api/deps.py` DI graph,
or any compliance-critical handler (recon, safeguarding, audit) can merge into `main`
if unit tests pass with mocks (mocks do not exercise DI wiring or lifespan hooks).

**Regulatory impact:** IL-CANON-04 §best-decision requires smoke evidence before
production-state change. FCA CASS 15 §15.10 requires daily reconciliation to run
reliably; a lifespan regression in the compliance API silently breaks recon without
CI detection.

**Severity:** CRITICAL
**Remediation:** ADR-035 Option (c) — `smoke-gate-mock.yml` as PR required check + `smoke-gate-full.yml` nightly

## Finding 2 — Branch Protection: Only Guardian Checks Required (CRITICAL)

**Evidence:** GitHub API `GET /repos/CarmiBanxe/banxe-emi-stack/branches/main/protection`:

```json
{
  "required_status_checks": {
    "strict": true,
    "checks": [
      {"context": "guardian-factory", "app_id": 15368},
      {"context": "guardian-project", "app_id": 15368}
    ]
  },
  "enforce_admins": {"enabled": false},
  "required_linear_history": {"enabled": false}
}
```

`quality-gate`, `test` (pytest coverage ≥80%), `ruff`, `semgrep`, `smoke-gate` —
**none are required checks**. The Guardian shim (ADR-024) is the sole blocker for
merging to `main`.

**Consequence:** A PR that fails pytest (coverage drops below 80%) or Semgrep (new
security finding) can still merge to `main` if Guardian checks pass. The quality-gate
workflow runs but its failure is advisory.

**Severity:** CRITICAL (G-CI-02)
**Remediation:** Branch protection PATCH to add `smoke-gate-mock / Smoke gate (mock stack)`
and `BANXE EMI Quality Gate / Pytest (coverage >= 80%)` as required checks

## Finding 3 — Pytest Suite: No Smoke Markers or Smoke Module

**Evidence:** Grep `@pytest.mark.smoke` across `banxe-emi-stack/tests/`:

```
$ grep -rn "@pytest.mark.smoke" banxe-emi-stack/tests/
→ (no output)
```

```
$ ls banxe-emi-stack/tests/test_smoke/ 2>/dev/null
→ ls: cannot access 'tests/test_smoke/': No such file or directory
```

Existing marker usage: `@pytest.mark.asyncio`, `@pytest.mark.parametrize`,
`@pytest.mark.skip`. The `pyproject.toml` `[tool.pytest.ini_options]` does not
define a `smoke` marker.

**Files with "integration" or "e2e" in name (unit-level despite naming):**
- `tests/test_lifecycle_kyc_integration.py` — InMemory stubs only
- `tests/test_api_sca_two_factor_integration.py` — mocked SCA service
- `tests/test_openbanking_wave2.py` — `end_to_end_id` field in payload, not e2e test

No test file exercises a real service container.

**Severity:** HIGH (G-CI-01)
**Remediation:** Create `tests/test_smoke/test_smoke_mock.py` with `@pytest.mark.smoke`
covering 6 components per ADR-035 Smoke Surface Matrix

## Finding 4 — Docker-Compose Stacks Exist but Not Used in CI

**Evidence:** Docker-compose files found under `banxe-emi-stack/docker/` and `infra/`:

| File | Services included |
|------|------------------|
| `docker/docker-compose.master.yml` | postgres, redis, clickhouse, guardian, api |
| `docker/docker-compose.recon.yml` | postgres, redis, recon-service |
| `docker/docker-compose.psd2.yml` | adorsys-psd2, postgres |
| `docker/docker-compose.pgaudit.yml` | postgres with pgaudit extension |
| `docker/docker-compose.transaction-monitor.yml` | jube, marble, postgres, redis |
| `infra/keycloak-banxe-emi/docker-compose.yml` | keycloak, postgres |

None of these files are referenced in any `.github/workflows/*.yml`.

**Gap:** `docker-compose.master.yml` contains the minimal real-stack definition needed
for a full smoke run. It is available for `smoke-gate-full.yml` (nightly) without
modifications.

**Severity:** MEDIUM — assets available, not wired to CI
**Remediation:** `smoke-gate-full.yml` references `docker/docker-compose.master.yml`
for the nightly real-stack smoke

## Finding 5 — `quality-gate.yml` Pytest Job: Real App, No Service Containers

**Evidence:** `quality-gate.yml` test job:

```yaml
test:
  name: Pytest (coverage >= 80%)
  runs-on: ubuntu-latest
  needs: [ruff]
  steps:
    - name: Pytest with coverage
      run: |
        python -m pytest tests/ -v --tb=short \
          --cov=services --cov=api --cov=src \
          --cov-report=xml --cov-report=term-missing \
          --cov-fail-under=80
```

This job installs Python dependencies and runs the full pytest suite. The test suite
does import `api/main.py` for TestClient tests — so startup errors **would** be caught
here — but only if coverage ≥80% gate runs. Since `quality-gate` is not a required
check (Finding 2), this protection is advisory.

Furthermore, all tests use InMemory stubs; there is no real service container in the
job. A real KC token issuance, ClickHouse write, or Postgres connection failure would
not be detected.

**Severity:** MEDIUM — partial coverage; not enforced; not real-stack
**Remediation:** Make `quality-gate / Pytest (coverage >= 80%)` a required check (G-CI-02
phase 2); complement with `smoke-gate-mock.yml` for lifespan + DI coverage

## Finding 6 — Smoke Surface Gap Matrix

Components requiring smoke coverage per IL-CANON-04 §best-decision + GAP-REGISTER G-CI-01:

| Component | Handler / function | Mock available | Smoke test exists | PR gate viable |
|-----------|-------------------|---------------|------------------|---------------|
| Auth token issuance | `POST /auth/login` | `httpx.MockTransport` for KC | ❌ | Yes (≤3 min) |
| Audit trail append | `AuditTrail.log()` | `InMemoryAuditPort` | ❌ | Yes |
| Recon tick | `ReconciliationEngine.run_tick()` | `InMemoryReconAuditPort` | ❌ | Yes |
| Safeguarding health | `GET /safeguarding/healthz` | None needed (real handler) | ❌ | Yes |
| Guardian /audit POST | `GuardianFactory.audit()` | `MockGuardianFactory` | ❌ | Yes |
| KYC workflow stub | `KYCWorkflowPort.create_workflow()` | `MockKYCWorkflowPort` | ❌ | Yes |

**0/6 components have smoke test coverage.** All 6 are achievable with
`FastAPI.TestClient` + InMemory stubs within ≤3 min on GH Actions.

## Finding 7 — V-08 Gap Confirmed: Classified MEDIUM, Security-Critical in Practice

**Evidence:** `GAP-REGISTER.md:245`:

> G-CI-01: No end-to-end smoke gate before merge / auto-deploy — NEW 2026-05-05
> Source: V-08 MEDIUM in HANDOFF-2026-05-04.
> Risk: regressions only caught post-merge; production-state change without smoke
> evidence violates IL-CANON-04 §best-decision.

V-08 severity is MEDIUM in the handoff classification. In practice, a lifespan
regression that silently breaks the compliance API (safeguarding reconciliation, audit
trail, KYC) constitutes a FCA CASS 15 §15.10 evidence gap — which is a regulatory risk,
not merely an operational inconvenience. ADR-035 reclassifies the effective regulatory
risk as HIGH for compliance-critical paths.

**Severity:** MEDIUM → HIGH (reclassified for regulatory impact)
**Remediation:** ADR-035 Option (c)

## Remediation Path

ADR-035 (Proposed, same PR) addresses all findings. Implementation:
1. `tests/test_smoke/test_smoke_mock.py` — 6 smoke steps, `@pytest.mark.smoke`
2. `smoke-gate-mock.yml` — PR required check workflow (≤3 min)
3. Branch-protection PATCH — add `smoke-gate-mock / Smoke gate (mock stack)` to required checks
4. `smoke-gate-full.yml` — nightly real-stack smoke (≤12 min, Docker on GH Actions)
5. Audit trail event on nightly smoke failure (ADR-027 buffer)

Gap status: **G-CI-01 OPEN**, **G-CI-02 OPEN**.
Both close on implementation PR merge with evidence (smoke-gate-mock green + branch-protection update confirmed).
