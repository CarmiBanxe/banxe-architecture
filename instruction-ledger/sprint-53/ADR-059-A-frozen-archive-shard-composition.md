# ADR-059-A: Frozen-archive + shard-composition strategy (amendment to ADR-059)

- Status: Accepted (S4 cutover 2026-06-08)
- Amends: ADR-059 (per-session shards) · Related: ADR-057 (append-only immutability), ADR-119 (stable IL numbering), I-28
- Ledger: IL-159 (parent)

## Context
ADR-059 replaced the monolithic INSTRUCTION-LEDGER.md with per-session shards. The pre-cutover historical range (IL-001..S4) needs a defined composition model: how the generated projection combines frozen history with new shards without re-litigating immutable records.

## Decision
1. **Frozen archive.** The historical ledger range is frozen verbatim into `ledger/FROZEN-ARCHIVE.md` — append-only, immutable (ADR-057), never regenerated.
2. **New entries = shards only.** Post-cutover, every entry is a shard file `ledger/entries/<session-id>/IL-<ISO8601Z>--<sid6>.md`; no direct writes to the monolith.
3. **Composition.** `INSTRUCTION-LEDGER.md` = `FROZEN-ARCHIVE.md` (frozen head) ⊕ deterministic shard projection (tail), regenerated by `build_ledger.py`. The monolith is a generated, read-only artifact.
4. **Numbering.** Frozen entries retain their historical IL-NNN; new shards receive max+1 over the frozen range + live shards (later centralized by the ADR-143/119 allocator).

## Consequences
History is immutable and parallel-safe; the projection is reproducible from shards + archive; enforced by `guardian-ledger-shards` (1:1 + rebuild) and `ledger-append-only`.
