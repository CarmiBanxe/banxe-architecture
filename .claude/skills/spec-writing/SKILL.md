# Spec Writing

## Purpose
Create IL records for work items and keep the governance registers current.

## Registers to update
- `INSTRUCTION-LEDGER.md` — the IL register (**generated** — see the mechanism note below).
- `COMPLIANCE-MATRIX.md` — updated when a task closes.
- `BLOCKED-TASKS.md` — when work is blocked.
- `PLANES.md` — strategic planning.

## Status flow
`OPEN → IN_PROGRESS → REVIEW → DONE | BLOCKED`

## Priorities
`P0 (critical) > P1 (important) > P2 (normal)`

## IL mechanism (CORRECTED — supersedes the legacy method)
> **This is a correction of an outdated instruction.** The previous form told the author to hand-write an
> `IL-XXX | Status | …` row directly into `INSTRUCTION-LEDGER.md`. That is **no longer valid** and would
> violate current canon.

- An IL is authored as a **per-session shard** under `ledger/entries/<session>/IL-<ISO8601Z>--<slug>.md`
  (append-only), **paired atomically** with the artifact it records.
- The **number is minted by `python ledger/build_ledger.py`** (max+1 over current `origin/main`) — **never
  hardcoded** (ADR-119 Rule 8).
- `INSTRUCTION-LEDGER.md` + `ledger/IL-SEQUENCE.json` are **generated by `build_ledger.py` and MUST NOT be
  hand-edited** (ADR-056/ADR-059). A duplicate IL is a rebase signal, not a question (ADR-119).

## Binding (factory canon)
No skill bypasses `quality-gate.sh` or invariants **I-01..I-28**; a new implementation requires an IL record
(I-28). Register/ledger updates are `[CLAUDE CODE]` state changes (`.claude/rules/agents.md`).
